# #536 PR 을 하위 작업 단위로 나누는 기준과 커짐 알림 (2026-10-29)

## 배경

앱 하나가 통째로 PR 하나가 되어 PR 이 커졌다(public-cloud #385 7,437줄, #400 5,783줄, #324 4,009줄). 원인은 "한 PR = 한 DEV 의 한 단계" 와 "안 끝난 개발은 브랜치에만" 이 겹친 것, 개발 PR 이 Spec 을 같이 고치면 섞임으로 잡힌 것, 커지는 걸 알려 주는 장치가 없던 것이다.

## 바뀐 것

| 곳 | 내용 |
|---|---|
| `rules/commit-and-pr.md`, `rules/governance.md` | 기준을 "하위 작업 이슈 하나 = PR 하나" 로 바꿈(#437 의 "한 DEV 의 한 단계" 대체). 섞임은 DEV 가 둘 이상이거나 SRS 와 개발이 함께일 때만. 개발 PR 이 같은 DEV 의 Spec 을 고치는 것, SRS+Spec 은 섞임 아님. "안 끝난 개발은 브랜치에만 / 쌓지 않기 / 승인된 PR 에 얹지 않기" 는 유지하되 하위 작업 하나가 080 에서 활성화되면 PR |
| `skills/deliver/SKILL.md` 8단계 | 섞임 판정 변경, "커짐 확인"(엔진 `checker.branch_growth`)과 판단 순서 4(커짐 → "여기까지를 PR 로 내고 나머지는 하위 작업으로 뺄까요?" 추천 보기, 막지 않음), 기존 "그 밖" 은 5 |
| `skills/start/SKILL.md` | 기능이 여럿인 개발은 하위 작업으로 쪼개 시작하도록 안내 |
| `checker/branch_growth.py`, `checker/tests/test_branch_growth.py` | `origin/{base}...HEAD` 의 `src/` 추가+삭제 줄을 세어 기준과 견줌. 시험 20개 |
| `docs/guide/harness-guide.html` | deliver 탭 세 갈래(+커짐), merge 탭 기준, start 탭 하위 작업 안내 |
| `plugin.json` | 0.10.138 |

## 설계

- 기준 값은 대상 저장소 `.github/branch-growth.yaml` 의 `notify_src_lines`(기본 1,000, 파일 없으면 기본). `risk-gate.yaml` 에 키를 넣지 않았다: 그 파일은 승인 판정 기준이고 모르는 키를 설정 오류로 막으며(`load_config`), 새 키는 엔진 태그가 나간 뒤에야 유효해 옛 판 저장소가 판정 불능이 된다. 승인 판정은 `src/` 크기를 보지 않는다(#436, #534).
- 종료코드: 0 이내·적용 안 함, 1 초과(알림), 2 검사 불능(git 실패, 설정 오류). 줄을 못 센 것을 통과로 넘기지 않는다(원칙 7). 바이너리 파일은 줄로 셀 수 없어 합에서 빼고 `uncounted` 로 알린다.
- 커짐 확인은 deliver 8단계에서 판단 순서와 무관하게 먼저 돈다(개발 도중 본인도 모르게 커지는 것을 잡는 게 목적). 안 끝난 개발(판단 2)에서도 `over` 면 "끝난 기능은 하위 작업으로 떼어 PR 내기" 보기를 더한다. 그 밖은 판단 4 에서 묻는다. 엔진 호출이 실패하거나 종료코드가 0·1 이 아니면 검사 불능으로 알리고 통과로 보지 않는다.
- git 출력은 `diff --numstat -z --no-renames` 로 읽는다. 따옴표 없이 한글 경로가 그대로 나오고, 못 읽은 레코드는 조용히 버리지 않고 검사 불능이다. 셀 수 없는 파일은 텍스트 출력과 deliver 안내에 "줄 수를 셀 수 없는 파일 N개" 로 보인다.
- 작업 트리에 `src/` 가 없어도 `origin/{base}` 에 `src/` 아래 추적 파일이 있으면 적용한다(브랜치가 `src/` 를 지웠으면 지운 줄을 센다). 기준에도 없을 때만(하네스 저장소 자신 등) `not_applicable` 이고, `git ls-tree` 가 실패하면 검사 불능이다.
- 기준 1,000줄은 public-cloud #200 이후 `src/` 를 고친 병합 PR 42개의 데이터(중간값 295.5줄, 1,000줄 초과 11개)에서 정했다. 사용자 확인 필요.

## 하지 않은 것

- risk-gate 크기 판정 변경은 #534, 진행 원장 마지막 PR 칸은 #535.
- 하위 작업으로 쪼개기를 훅으로 강제하지 않는다(deliver 의 추천 보기).
