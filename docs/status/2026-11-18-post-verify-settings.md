## 고친 것
1. **첫 화면에서 고른 프로젝트를 머리 줄이 따라가지 않음**(`app.js` `confirmPick` 의 Post 분기). Post 머리 줄 「보는 프로젝트」(#1070)는 고른 적이 없으면 서버 마지막 폴더를 쓰는데, 저장소 판정(`/api/repos`)을 세션 폴더가 바뀔 때만 다시 받아서, 첫 화면에서 `projA` 를 골라도 머리 줄은 고르기 전 마지막 폴더(`plainX`)로 남았다(홈 문구는 `projA` — 고치기 전 코드로 깨끗한 브라우저에서 재현). 전에 다른 프로젝트나 `모든 저장소` 를 골라 둔 사람도 그대로 남았다. 새 작업을 시작하면 그 폴더 프로젝트를 보는 것(#1070)과 같게, Post 는 `이 프로젝트로` 에서 고른 폴더를 보는 프로젝트로 두고 저장소 판정을 다시 받는다.
2. **한도 켜기 확인 카드의 `지금`·`바꾼 뒤` 이름표가 어두운 모드에서 거의 안 보임**(`theme-post.css` 끝): app.css 의 Sauce 색 `#55625f` 그대로였다 → Post 흐린 글 색(`--lmuted`). 아래 안내 문장(`끄면 지금 값 그대로 돌려놔…`)이 명령 글에 붙어 있던 것도 위 문장과 같은 10px 간격.
3. **원래 값 기억 파일 없이 켜져 있을 때 스위치를 누르면 같은 말이 두 번**: 이유 문구(`…끄기로 되돌릴 수 없어. settings.json 의 statusLine 을 직접 고쳐 줘.`) 아래에 `끄지 못했어 · 원래 statusLine 값을 기억한 파일이 없어서 되돌릴 수 없어. …` 가 더 붙었다. 이 상태에서 끄기는 늘 같은 이유로 실패하므로 Post 는 스위치를 막는다(이유 문구는 그대로).
4. **한도 문구가 위에 보인 긴 settings.json 경로를 한 번 더 보임**: `바꾸는 파일 · <경로>` 바로 아래 `<경로> 가 올바른 JSON 이 아니어서…` 라 390 에서 같은 경로가 네 줄씩 두 번 접혔다. Post 만 문구 안 경로를 `이 파일` 로 줄인다(`이 파일이`·`이 파일을`·`이 파일의`, 실패 문구에도 같게).

독립 리뷰(sonnet, 읽기 전용) 반영: (1) 저장소 판정을 받는 중에 `이 프로젝트로` 를 누르면 늦게 온 옛 응답이 `repos.sig` 를 다시 써서 다시 받지 않을 수 있었다 → `repos.gen` 세대 번호로, 받는 동안 다시 받으라고 한 응답은 `sig` 를 남기지 않는다(`ensureRepos` 는 Post 에서만 돈다). (2) 새 node 시험에 `skipif(not NODE)`. 남긴 것: 판정 응답이 오기 전(보통 1초 안) 머리 줄에 옛 마지막 폴더가 잠깐 보일 수 있다.

확인: 고친 뒤 처음 화면 끝까지를 Post 라이트·다크 × 1440·390 에서, 한도 화면(확인 카드·깨진 JSON·기억 파일 없음)을 같은 네 조합 중 각 경우 두 조합 이상에서 다시 찍어 봤다(가로 넘침 0, 콘솔 오류 0).
