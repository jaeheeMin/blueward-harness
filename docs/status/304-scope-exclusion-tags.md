# #304 SRS 하지 않는 것 항목에 REQ 꼬리표와 번호 찜 겹침 확인 (2026-10-14)

범위 절의 "하지 않는 것" 목록은 한데 모여 있어서 어느 요구사항에서 뺀 일인지 기계가 몰랐고, 그래서 뺀 일이 새 REQ 로 등록돼도 미리 못 잡았다(public-cloud 의 DEV-002/DEV-003 Launchpad 타일 쪼개짐). public-cloud SRS 에 이미 있던 `- 회계전표 역분개·취소, 승인 워크플로 (REQ-001)` 표기를 규칙으로 정했다(사용자 결정 2026-10-14).

**표기.** 항목 맨 끝의 `(REQ-001)`, `(REQ-001, REQ-002)` 가 꼬리표이고 그 요구사항에서 뺀 일이다. 꼬리표가 없으면 프로젝트 전체에서 하지 않는 일이다. 전각 괄호·쉼표도 받고(`（REQ-001）`), 항목 끝 마침표 뒤에 와도 된다. 머리말 줄에 이어 쓴 `A, B (REQ-001)` 은 쪼갠 뒤 B 에만 붙는다(들여쓴 목록은 줄마다 한 항목이라 줄 안의 쉼표는 쪼개지 않는다). 식은 `plugins/harness/skills/start/reserve_number.py` 와 `checker/risk_gate.py` 의 `EXCLUDED_TAG_RE` 두 곳에 있고(플러그인은 엔진을 import 못 해 파서가 따로다) 테스트가 같은 식인지 본다. `req_cross_reference` 는 `### REQ-n` 상세 절만 보므로 범위 절의 꼬리표는 위반이 아니다(public-cloud 의 기존 꼬리표가 통과 중인 것과 같다). 엑셀 산출(`export.parse_srs`)은 `## 요구사항` 절만 읽어 범위 절은 나가지 않는다(테스트로 고정).

**번호 찜(`reserve`·`claim`).** 새 제목(앞 `[DEV-…]` 뗌)을 공백·대소문자 정리한 뒤, origin/main SRS 의 "하지 않는 것" 항목(꼬리표 뗌)과 포함 관계(한쪽이 다른 쪽을 포함)이거나 핵심 단어가 겹치면 종료코드 4 로 멈춘다. 핵심 단어 겹침은 "하지 않는 것" 항목 비교에만 쓴다(기존 REQ 제목 비교는 포함만): 소문자화한 영숫자·한글 토큰 중 2자 이상만 남기고, 공유 토큰이 2개 이상이면서 새 제목 토큰의 2/3 이상이면 겹침이다. 불용어 목록은 두지 않았다 — 공유 토큰이 둘 이상이어야 해서 `조회`·`앱` 같은 일반어 하나로는 안 멈추고, 실제로 돌려 보니 필요하지 않았다. stdout JSON 에 `excluded_matches: [{"item": 항목, "reqs": ["REQ-001", …]}]` 가 늘었고(없으면 빈 목록, 기존 `matches` 와 함께 나올 수 있다) `reqs` 가 비면 프로젝트 전체에서 안 하는 일이다. 오탐 기준: 기존 제목 겹침과 같은 상수 `MIN_TITLE_LEN`(정규화 뒤 4자 미만이면 새 제목도 항목도 비교에서 뺀다). 항목 쪽에는 더 센 기준을 두지 않았다 — 항목은 문장이라 새 제목이 항목 안에 들어가는 방향이 주된 겹침이고, 항목이 긴 문장일 때 새 제목이 그 안의 단어 몇 개와 같은 것은 우연이 아니라 실제 겹침일 가능성이 높아서다. `--confirmed-new` 로 넘기는 흐름·SRS 없음(건너뜀)·읽기 실패(종료코드 2)는 그대로다. 꼬리표가 없는 기존 SRS 도 "하지 않는 것" 항목과 겹치는 새 제목이면 멈춘다(그게 이 변경의 목적). **괄호 속 부연은 비교에서 뺀다.** 항목 `판매오더 생성·변경·삭제 (조회 전용)` 의 `조회`·`전용` 때문에 `판매오더 조회`·`판매오더 상세 조회`·`조회 전용 화면` 이 멈추는 오탐이 있어, 항목 쪽 토큰과 포함 판정 텍스트에서 괄호 안 내용을 공백으로 바꿔 뺀다(보여 주는 항목은 원문 그대로). 이 셋은 안 멈추고, `Launchpad 타일 노출` 은 괄호 안 `IAM App…` 을 빼도 `launchpad`·`노출` 로 계속 멈춘다. 경계 사례: `판매오더 변경 이력` 은 `판매오더`·`변경` 이 겹쳐(3개 중 2개) 멈춘다 — 변경을 안 하기로 한 항목이라 겹침이 실제일 수 있고 멈춰도 질문 하나라 허용했다. 같은 본문이 꼬리표만 달리 두 번 나오면 번호를 합친다(엔진·플러그인 모두).

**검증.** 사건 직전 SRS 로 `Launchpad 타일 노출` 이 `Fiori Launchpad 노출(IAM App, …)과 …` 항목에 걸린다(공유 `launchpad`·`노출`, 새 제목 토큰 3개 중 2개). 한계: 토큰은 조사가 붙은 채라 `노출과` 와 `노출` 은 다른 토큰이고, 새 제목 단어가 하나만 겹치면(`Launchpad 타일`) 안 걸린다.

**risk-gate `split_hint` (b).** "하지 않는 것" 항목을 꼬리표를 뗀 형태로 비교한다. 그래서 **꼬리표만 붙이거나 떼거나 번호를 바꾼 변경은 항목이 바뀐 근거로 치지 않는다**(기존 SRS 에 꼬리표를 붙이는 PR 이 새 REQ 와 함께 오면 오탐이 나기 때문). 항목 내용이 지워지거나 바뀐 경우만 근거이고, 그 항목에 꼬리표가 있었으면 근거 문구에 `"항목" (REQ-002 의 하지 않는 것)` 이 붙는다. 꼬리표 번호가 다른 REQ 로 옮겨진 경우(내용 동일)는 근거가 아니다.

**스킬·틀·길잡이.** start·srs·spec 스킬의 종료코드 4 안내에 `excluded_matches` 를 더했고, srs 스킬에 꼬리표를 붙이는 규칙 절을 넣었다. SRS 틀(`templates/harness/SRS.md`)의 범위 절에는 목록 아래 별도 문단으로 꼬리표를 안내한다 — 목록 안에 들여쓴 줄로 적으면 안내 문장이 항목으로 읽히기 때문이다. 길잡이는 SRS 탭(꼬리표 callout), 막혔을 때 탭의 종료코드 4 행, risk-gate 행을 고쳤고 레일을 "harness 0.10.65, public-cloud main 기준 (2026-10-14)" 로 바꿨다. 병합 뒤 아티팩트 재게시는 남아 있다.

**실데이터(public-cloud SRS, 함수 수준).** main SRS 의 항목 8개를 읽고(꼬리표는 `회계전표 역분개·취소, 승인 워크플로 (REQ-001)` 하나) 엔진 파서와 플러그인 파서의 결과가 같다. `판매오더 생성`·`회계전표 역분개`·`승인 워크플로` 는 멈춘다(뒤의 둘은 `reqs: ["REQ-001"]`). `구매요청 승인`·`재고 조회 앱`·`판매오더 엑셀 다운로드`·`취소`·`판매오더 조회 앱 필터 개선` 은 main 과 사건 직전 SRS 둘 다에서 안 멈춘다. main 에는 Launchpad 항목이 이미 빠져(REQ-002 범위로 옮겨짐) `Launchpad 타일 노출` 이 안 멈추고, 사건 직전 SRS(`190a5d7~1`)로는 멈춘다. 토큰 겹침이 더 잡는 것: `커스텀 테이블 추가`(`커스텀 테이블, Custom Query…` 항목), `외부 API 연동`(사건 직전 SRS 의 `…외부 소비용 API 서비스` 항목) — 둘 다 실제로 겹치는 일이라 오탐으로 보지 않는다.

**미결.** 조사가 붙은 한글 단어(`노출과`)는 다른 토큰으로 본다(형태소 분석은 하지 않았다). 병합 뒤 길잡이 재게시. Plugin version: main 이 0.10.64(#302 병합)라 0.10.65.
