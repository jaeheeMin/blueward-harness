## Spec 간 SAP 객체 겹침 경고와 교차 검사 스위치(#292, 2026-10-13)

한 개발이 DEV 둘로 쪼개지면(public-cloud PR #177) 두 Spec 이 같은 객체를 만들거나 고치게 된다. 새 모듈 `checker/overlap.py` 의 `check_overlap(root)` 가 `docs/spec/DEV-*.md`(루트 직속, 번호 짝 검사와 같게 `DEV-` 로 시작하는 Spec 만) 마다 `## 사용 객체` 표(#287)를 읽어 작업이 `생성`·`수정` 인 행의 `(종류, 이름.upper())` 가 Spec 둘 이상에 나오면 **경고**한다(Spec 경로·DEV 번호·각자의 작업). `참조` 행은 비교하지 않고, 한 Spec 안의 중복 행은 겹침이 아니다. 이름이 비었거나 영문자(또는 `/` 네임스페이스)로 시작하지 않는 행(`미정`, `-`)은 비교에서 빼고 `name_tbd` 개수로만 남긴다(코멘트에 "이름 미정 n건"). 경고만 하므로 위반은 없고 결과는 pass(경고 포함)/cannot_check/skipped(`docs/spec/` 없음)다. 절이 없는 Spec 은 비교에서 빼고 `no_table` 개수로만 남긴다. 검사 불능(종료코드 2): 읽지 못함, 절은 있는데 표가 없음, 표 머리가 `종류|이름|작업|비고` 가 아님, 칸 수가 다름, 작업이 생성·수정·참조가 아님, 이름은 있는데 종류가 빔 — 그 Spec 경로와 사유를 싣는다. 표 파서는 `md_table` 규칙과 같은 것을 쓰려고 `checker/rules/md_table.py` 에 `read_section_table`·`plain_cell` 을 공개했다(규칙 동작은 그대로). `scripts/check_changed.py` 는 바뀐 파일에 `docs/spec/` 가 있으면 돌려 리포트 키 `overlap` 으로 합치고, `render_report.py` 에 "객체 겹침" 절(경고 표, 표 없음·이름 미정 n건, 검사 불능)을 더했다.

**스위치:** `rules/cross-checks/switches.yaml` 의 `번호_짝`·`객체_겹침`(true/false)로 번호 짝(#284)과 객체 겹침을 각각 끈다. 파일이 없거나 키가 없으면 켠다(지금 동작 유지). 모르는 키·불린이 아닌 값·깨진 YAML 은 `cross_checks` 키에 검사 불능을 싣고 종료코드 2(`checker/cross_switches.py`) — 켜진 건지 꺼진 건지 모르니 두 검사를 돌리지도 건너뛰지도 않는다. **판단 — 위치:** 엔진 로더가 `rules/` 최상위 `*.yaml` 을 전부 문서 규칙 파일로 읽어 최상위에 두면 '관할 이 없다' 며 모든 검사가 멈추므로, 로더가 읽지 않는 하위 폴더 `rules/cross-checks/` 에 뒀다(옛 엔진도 영향 없음). **판단 — 꺼진 검사:** 돌릴 조건인데 스위치가 꺼져 있으면 리포트에 `{"status": "disabled"}` 를 싣고 코멘트에 "객체 겹침(번호 짝): 이 저장소 설정(rules/cross-checks/switches.yaml)으로 꺼져 있음" 한 줄을 남긴다 — 조용히 빠지면 왜 검사가 안 보이는지 알 수 없다. 종료코드는 0 이다. 스위치는 해당 검사를 돌릴 PR(번호 짝은 SRS·Spec·원장 변경, 겹침은 Spec 변경)에서만 읽는다. 스켈레톤에 `rules/cross-checks/switches.yaml`(둘 다 true, 끄는 법 주석)을 넣었고 `test_scaffold` 의 기대 파일 목록에도 더했다. 켜는 순서: 이 파일은 v0.10.62 이상 엔진이 읽는다 — 옛 엔진은 파일을 모르고 두 검사를 항상 돌린다(해롭지 않다).

**미결:** 스켈레톤 `rules/README.md` 에 (a) 스위치 설명 (b) "`md_table` 은 엔진 v0.10.59 이상(stable)에서만 동작" 안내를 넣으려 했으나 편집 훅이 두 번 막았다(편집 대상 스켈레톤 `rules/spec.yaml` 에 이 저장소 훅이 쓰는 구판 엔진이 모르는 `md_table` 이 있어 설정 오류). 병합 뒤 엔진 태그가 붙고 나서 README 만 따로 고친다.

테스트 `checker/tests/test_overlap.py`. 한계: 객체 이름은 `(종류, 대문자)` 만 비교하므로 네임스페이스가 다른 같은 이름은 다른 객체로 본다. Spec 은 `docs/spec/` 직속만 본다. 실제 PR 코멘트 렌더링은 아직 못 봤다. Plugin version 0.10.62.
