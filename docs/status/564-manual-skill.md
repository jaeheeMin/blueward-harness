# #564 사용자 매뉴얼 스킬 추가 (2026-11-01)

## 배경

#561(pptx 산출 엔진)과 #576(작업본 머리 `버전:` 이 파일명 버전) 위에서 매뉴얼을 쓰고 산출하는 스킬을 만든다. 사용자 결정(2026-10-31): 매뉴얼은 `docs/manual/<LoB>/` 아래 업무 제목별 여러 파일이고, 한 파일에 묶은 개발 건(DEV)을 작업본에 적는다. 디자인은 Project Repository 의 Blueward 양식을 쓰고, 화면 위 번호·빨간 네모는 캡처 도구(#533, 아직 없음)가 그림에 그린다. 스킬은 그림 경로만 받는다. 양식은 바뀔 수 있어 스킬·엔진에 양식 고유 글자를 박지 않는다.

## 바꾼 것

- `plugins/harness/skills/manual/SKILL.md`(새): `/harness:manual`. 작업본 형식, 0단계 브랜치 확인(start 의 "다른 스킬이 부르는 브랜치 확인"), 만들기(LoB·업무 제목·묶을 DEV 묻기 → Spec·기존 매뉴얼 읽기 → pptx 지도 찾기, 없으면 `--dump` 안내하고 멈춤 → 초안), 캡처 없는 화면(목록으로 알리고 산출하지 않음), 산출(`--check` 먼저, 엔진 판은 spec 스킬과 같은 `engine_spec.py`·`uvx`), 종료코드별 안내(3 은 `layout-unchecked` 면 PowerPoint 로 사람이 확인), 고치기·버전 올리기(이전 판 보존), 기존 md 매뉴얼 옮기기, 규칙 설치.
- `plugins/harness/skills/manual/manual.yaml`·`manual-output.yaml`·`manual-template.md`(새): Project Repository 의 `rules/manual.yaml`·`rules/manual-output.yaml`·`templates/harness/manual.md` 로 복사해 쓰는 사본. 작업본(`docs/manual/**/*.md`)은 파일명 `^\d+\..+\.md$`·필수 절·`묶은 개발 건` 표·`form_columns`, 산출 pptx(`docs/manual/**/*.pptx`)는 파일명 패턴만 본다. 두 관할을 나눈 까닭은 `form_columns` 가 pptx 를 텍스트로 읽지 못하고, 지도의 `검사_규칙` 이 첫 filename 패턴을 산출 pptx 이름에 적용하기 때문이다.
- `checker/export.py`: pptx 지도의 `산출.폴더` 에도 `{LoB}` 같은 자리를 쓸 수 있다(파일명과 같은 자리 규칙). 값에 `/ \ : * ? " < > |`·`..` 가 있으면 거부(폴더를 벗어나지 못함). 매뉴얼을 LoB 폴더별로 내기 위해 필요했다. `{` 가 없는 폴더는 이전과 같다.
- `plugins/harness/skills/spec/form-map.md`: 지도 예시의 `검사_규칙`·`산출.폴더` 고침, "사용자 매뉴얼 작업본" 항목 추가.
- `CLAUDE.md` 스킬 표, `plugins/harness/README.md`(트리·스킬 표), `docs/guide/harness-guide.html`("문서 작업" 묶음에 "사용자 매뉴얼 만들기" 탭, 앞뒤 탭의 이전·다음 버튼, 레일 "harness 0.10.147" 표기).
- 시험: `checker/tests/test_export_pptx.py` 에 매뉴얼 작업본 경로 시험(양식 밖 항목·파일명·묶은 개발 건 표 거절, 산출 폴더 자리, 경로 벗어남 거부, 캡처 없는 화면이 화면별로 나옴). `test_engine_pin.py`·`test_plugin_layout.py` 의 스킬 목록에 manual 추가.
- plugin.json version 0.10.147.

## 작업본 형식

`docs/manual/<LoB>/<번호>.<업무 제목>.md`. 머리 `버전: 0.1`, `## 묶은 개발 건`(`| DEV | 제목 |`), `## 양식 항목` 아래 `### <양식> · 표지/목차/끝` 과 `### <양식> · 본문 · <화면 이름>`(칸 표, `#### 그림` 저장소 루트 기준 PNG 경로, `#### 번호 설명` 번호 목록). 표지 `제목` 값은 `<번호>.<업무 제목>`, `LoB` 값은 폴더 이름과 대소문자까지 같아야 한다(아래 "독립 검토 뒤 보완" 1).

## 독립 검토 뒤 보완

1. **자리 폴더 = 작업본 폴더.** 방식: 지도 키 없이 일반 규칙. `산출.폴더` 에 `{자리}` 가 있으면 채운 폴더가 작업본(`--spec`)이 있는 폴더와 대소문자까지 같아야 하고, 다르면 `산출.폴더` 항목으로 거부한다(산출물은 작업본 옆에 놓인다). 자리가 없는 폴더(xlsx 포함)는 영향이 없다. 지도·엔진에 양식 글자는 없다.
2. **폴더 조각 검증**(`_bad_folder_piece`): 빈 값, 제어 문자, `/ \ : * ? " < > |`, 점만 있는 값(`.`·`..`·`...`), 끝의 점·공백, Windows 예약어(CON·PRN·AUX·NUL·COM1-9·LPT1-9, 확장자가 붙어도 대소문자 무관).
3. **보고 위치.** 폴더 문제는 `산출.폴더 {LoB}` 항목과 "산출 폴더" 사유로 나온다(빈 값도 파일명 사유가 아니라 폴더 사유). 폴더를 못 정하면 쪽을 채우기 전에 거부한다(제어 문자가 XML 쓰기에서 죽던 것을 막음). 템플릿에 `\` 를 쓴 경우는 값 탓이 아니라 지도 오류(종료 2)로 안내한다.
4. 위 시험을 `test_export_pptx.py` 에 더했다(대소문자 다름 3, 쓸 수 없는 값 14, 빈 값, `\` 지도 오류, 자리 없는 폴더는 위치 무관).
5. `manual-output.yaml` 의 파일명 패턴은 지도 `산출.파일명` 에서 끌어올 수 없어 느슨한 사본이다. 첫 판 0.1·0.1 씩 올림·파일명 제목과 표지 `제목` 일치는 강제하지 않는다고 스킬에 적었다.

## 확인한 것

- 저장 Hook·PR 의 `form_columns` 는 #561 에서 이미 pptx 지도를 대조한다. 매뉴얼 작업본 경로(`docs/manual/<LoB>/…md`)에서 걸리려면 Project Repository 에 그 경로를 관할하는 규칙 파일이 있어야 하는데 public-cloud 에는 `docs/manual` 관할 규칙이 없다(빈 곳). 이 PR 이 사본 규칙을 스킬 폴더에 두고 시험으로 쓰임을 확인했다(양식 밖 쪽·소제목 거절, 파일명, 묶은 개발 건 표). public-cloud 에 넣는 것은 별도 작업이다. scaffold 골격에는 넣지 않았다(매뉴얼을 안 쓰는 저장소까지 규칙이 생기는 것을 피함).
- 산출물에 양식 예시 글자가 남는지: 엔진은 지도의 `유지` 가 있는 쪽(본문)만 안 가리킨 도형을 지운다. `유지` 가 없는 쪽(표지·목차·끝)은 `칸`·`지우기`·`목록` 이 가리킨 도형만 바뀌고 나머지 글은 남으며 이를 막는 검사는 없다(xlsx 의 `견본_검사` 에 해당하는 pptx 기능 없음). 새로 만들지 않았고 스킬에 "지도의 `칸`·`지우기` 에 넣어야 한다, PowerPoint 확인 때 본다" 로 적었다.
- 없는 그림 경로 거부는 엔진에 있다(화면마다 `problems` 한 줄). 시험으로 두 화면이 각각 나오는 것을 확인했다.
- 그림 파일 이름 끝 `_v<판>` 규칙(#348)은 xlsx 산출에만 있고 pptx 산출은 검사하지 않는다. 스킬에는 권장 관례로만 적었다.

## 확인하지 못한 것·남긴 것

- 실물(public-cloud main 의 Blueward 양식) 확인은 끝내지 못했다. 사유는 작업 보고에 적었다.
- 같은 DEV 를 두 매뉴얼이 묶는지, 표지 `제목` 과 파일명이 같은지는 검사하지 않는다.
- 캡처 도구(#533)와의 연결은 없다. 그림은 사람이 경로를 준다.
- 병합 뒤 엔진 태그가 새로 붙는다. public-cloud 에 규칙·틀·지도를 넣는 것은 별도 작업이다.
