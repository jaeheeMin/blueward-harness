# #496 pr-tamper-alert 가 작성자 본인의 push 에도 runner 를 띄워 Actions 분을 씀

## 배경

- 2026-10-25~27 public-cloud 에서 pr-tamper-alert 가 19회, 178분을 썼다. 실행 161회 중 알림은 0건이었다.
- 대부분 PR 작성자 본인의 push 였다. 판정 단계가 "작성자 본인이면 알리지 않음" 으로 끝나지만, 그 판정이 job 안에 있어 runner 가 떠서 1분씩 과금됐다.
- 건너뛴 job 은 과금되지 않는다(10-17·10-19 실측).

## 결정

- 작성자 본인·봇 판정을 job 수준 `if` 로 올렸다. 이벤트 조건(synchronize, 리뷰 해제)은 그대로 두고 `&& (sender 가 비었거나 || 작성자가 비었거나 || (sender != 작성자 && sender.type != 'Bot'))` 를 붙였다.
- 두 계정 중 하나라도 비면 건너뛰지 않고 돌린다. 빈 값끼리 같다고 건너뛰면 "판정 불능" 이 통과처럼 사라진다(원칙 7). 판정 단계가 그대로 실패시킨다.
- 판정 단계의 비교는 안전망으로 그대로 둔다. 리뷰 해제에도 같은 `if` 가 걸린다 — 판정 단계가 이미 두 이벤트 모두 작성자 본인·봇을 알리지 않았기 때문이다.
- 식의 문자열 `==`·`!=` 는 대소문자를 구분하지 않는다(GitHub 식 문서). 판정 단계가 소문자로 바꿔 비교하는 것과 같다.
- 테스트: 워크플로 `if` 를 파이썬으로 옮겨 평가해 작성자 push 건너뜀, 다른 계정 push 실행, 봇 건너뜀, 빈 값 실행, 다른 이벤트 종류 불변을 확인한다.
- 길잡이 pr-tamper-alert 줄에 작성자 본인·봇 push 는 job 을 띄우지 않는다고 적었다.
- plugin version 0.10.126.

## 남은 일

- 병합 뒤 public-cloud 에서 작성자 본인이 push 했을 때 alert job 이 skipped 로 뜨고 분을 쓰지 않는지, 다른 계정 push 는 여전히 판정이 도는지 확인한다.
- 병합 뒤 길잡이 아티팩트를 다시 올린다(`docs/guide/README.md`).
