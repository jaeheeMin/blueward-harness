# #826 웹 콘솔 서버가 화면에 내는 이유·오류 문구의 합니다체를 반말로 (2026-11-09)

## 배경
웹 콘솔 화면 글은 반말이 기본인데(#794·#818), 서버(`plugins/harness/console/*.py`)가 만들어 화면에 그대로 내는 이유·오류·안내 문구는 합니다체("~습니다", "~입니다", "~하십시오", "~세요")가 남아 있었다. #818 은 "지금 하는 일"·쉬는 터미널 안내만 고쳤다.

## 바꾼 것
`니다|십시오|세요` 를 .py 에서 찾아 브라우저로 나가는지 코드 흐름(reason·error·message 필드, HttpError 본문, 작업 로그)으로 나눴다. 나가는 것만 어미를 바꾸고 경로·명령·이유는 그대로 뒀다.

| 파일 | 전 → 후 (예) |
|---|---|
| `server.py` | `LOADING_REASON` "읽는 중입니다." → "읽는 중이야.", `HANDOFF_GUIDE` "…없습니다 … 시작하십시오." → "…없어 … 시작해 줘.", "브라우저를 열지 못했습니다." → "…못했어.", "갈래 데이터를 쓸 수 없습니다." → "…없어.", 프로젝트 준비 조건 이유("…확인하지 못했습니다" 등), 갈래·스킬·세션·요청·작업 없음 안내, 파일 읽기·열기·내려받기 오류, 인계(next) 실패 이유, 폴더 고르기 오류, 인증·링크 만료 안내 |
| `platform_compat.py` | `CLAUDE_MISSING` "…찾을 수 없습니다 … 보십시오 … 권합니다" → "…없어 … 봐 줘 … 권해", `PICK_FALLBACK` "적어 주세요" → "적어 줘", 폴더 선택 창 오류, 열기 오류 |
| `flows.py` | `NEXT_HINT` "시작하십시오." → "시작해 줘.", 갈래 데이터 읽기 오류, 단계 진행·건너뛰기 안내, 다음 갈래 정하기 불가 이유 |
| `gitstate.py` | git·gh 읽기 실패 이유 전부, 승인자 판정 이유 |
| `devready.py` | 개발 준비 상태 이유 전부 |
| `docfiles.py` | 문서 경로 거절·미리보기 오류 |
| `analysis.py` | 첨부 경로 거절 이유, 분석 실패 이유 |
| `managed.py` | 세션에 보내지 못한 오류, 중단 로그 |
| `store.py` | 대기 요청 과다, 쉬는·끝난 터미널 세션 안내 |
| `trouble.py` | 문제·해결 기록 입력 오류 |
| `plugin.json` / `whats_new.json` | 0.10.235 → 0.10.240, 팀원용 한 줄 |
| `harness-guide.html` | 레일 판 표기만 0.10.240 (바꾼 문구를 인용한 곳은 없었다) |

같이 고친 시험: `test_web_console.py` 의 `CLAUDE_MISSING` 일부 문구, 중단 로그, `gitstate.status_paths` 사유 3곳.

## 일부러 안 바꾼 것
- AI(Claude)에게 가는 글: `analysis.py` 의 분석 프롬프트, `handoff.py` 의 인계 첫 단계 문장, `hooks_api.py` 의 Stop 훅 지시문, `managed.py` 의 권한 거부 message(Claude 에게 돌아가는 값).
- 터미널·로그로만 나가는 글: `open.py` 의 CLI 출력, `server.py` 의 stderr 출력과 서버 시작 실패 사유(`write_error_file`), 주석·docstring, `platform_compat.py` 의 폴더 선택 창 Description(윈도우 기본 창).
- API 계약 오류(UI 가 정상 사용 중엔 만들지 않는 요청 검증): "cwd 가 필요합니다", "flowId 가 필요합니다", JSON·Content-Length·Host·Content-Type·메서드·"decision 은 … 중 하나여야 합니다" 등.
- `flows.py` 의 갈래 데이터(workflow.json) 검사 오류 목록(`validate` 계열): 하네스 개발자용 오류라 판단이 애매해 그대로 둠. 시험(`test_web_console.py` 3374~3376)도 이 문구를 비교한다.

## 메인 검토에서 고친 것
- `server.py` "쓸 수 없는 갈래입니다: …" 두 곳이 "갈래야:…" 로 바뀌며 쌍점 뒤 빈칸이 빠짐 → "갈래야: …"
- "이미지 파일만 내려줍니다." → "내려줘." 는 부탁으로 읽힘 → "이미지 파일만 내려받을 수 있어."
- `store.py` `CANNOT_SEND_IDLE` 은 #818(PR #824)이 같은 줄을 "쉬는 터미널 세션이라 여기서는 새로 시킬 수 없어. 터미널에서 이어서 말해 줘." 로 고쳤다 → 같은 문장으로 맞춤(합칠 때 충돌 방지)

## 화면 코드(app.js)
- `static/app.js` 1063·1595줄 "입력칸 아래 알림"(`…이어서 처리합니다.` / `…전달했습니다.` / `보내지 못했습니다:`)은 서브에이전트가 고치려다 편집 훅에 막혔다. 원인은 파일의 기존 빈 catch(583줄 `lsSet`, #796, CR-007)였고 우회하지 않고 멈췄다. 메인이 그 catch 를 #827 과 같은 내용(`console.warn`)으로 고친 뒤 세 문구를 "지금 단계가 끝나면 이어서 할게." / "이 작업에 전달했어." / "보내지 못했어:" 로 바꿨다(같은 줄을 같은 내용으로 고쳐 #827 과 합칠 때 충돌하지 않는다).
- `static/*.js` 에는 이 밖에도 화면에 보이는 합니다체가 59곳 남아 있다(app.js 46·flow-ui.js 11 등). app.js 를 크게 고치는 #819·#827 뒤에 하도록 #840 으로 남김.
