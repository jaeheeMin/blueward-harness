# #993 시안 치수 검사의 G-11 홈 숫자 칸을 다섯 칸 기준으로 (2026-11-15)

## 배경
G-11 홈 시안은 기록 기능을 넣기 전에 그린 것이라 숫자 칸이 네 개다. 기록 기능과 함께 나온 G-24 시안은 다섯째 칸 '팀 기록' 을 넣은 다섯 칸이다. 콘솔 홈은 G-24 시안대로 그려져 있다. 그래서 G-11 하나만 계속 실패했다. #855 는 이 차이를 사용자 확인 없이 "알려진 차이" 로 제외했다.

사용자 결정(11-15): 기능을 더하면서 새 시안이 나오면, 앞 시안에도 그 기능이 있는 것으로 본다. 메뉴 다섯 칸 결정(11-07, #779)과 같은 원칙이다.

## 한 것
| 파일 | 내용 |
|---|---|
| `checker/tests/console_mockup/compare.py` | `borrow_later_mockup`: 요소 설정 `{"from": 화면}` 이면 그 시안에서 같은 너비의 기대값을 가져온다. `{"below": {"screen", "element"}}` 이면 그 요소의 높이가 늘어난 만큼 세로 위치(y·tcy) 기대값을 내린다. 원래 기준값은 바꾸지 않는다 |
| `check_console.py` | 기대값을 가져올 때 위 함수를 거친다 |
| `screen_config.py` | G-11: `tile` 은 `from: G-24`, `light`('내 세션' 판)는 `below: G-24 tile`, '아직 안 풀린 문제' 글자 확인을 더한다. `ready` 를 `[data-pr-tile]:not([hidden])` 로 바꾼다(아래) |
| `checker/tests/test_console_mockup_compare.py` | 새 시험 5개 |
| `docs/design/web-console.md` | 대조 절에 이 원칙을 적는다 |

## 고치다 찾은 것: G-11 상태가 잴 때마다 달랐다
'승인 기다리는 PR' 칸은 gh 를 읽은 뒤에야 보인다. 그런데 `ready` 는 칸(`.tile2`)이 나타나는 것만 기다렸다. 그래서 이 칸이 늦게 뜬 상태로 재는 일이 생겼다.
- 1차 실행: 1440 은 네 칸으로 재서 너비 통과, 1280 은 다섯 칸으로 재서 실패.
- 2차 실행: 두 너비 모두 네 칸(그림으로 확인).

이 때문에 예전 결과의 "1280 너비만 실패" 도 상태가 흔들린 탓이었다. 지금은 그 칸이 보일 때까지 기다린다.

## 확인
- 고치기 전: G-11 실패 5건(1440·1280 tile.h +32.5, light.y +32.5, 1280 tile.w -49.8). G-24 는 통과.
- 고친 뒤: G-11 을 두 번 따로 돌려 둘 다 통과. 24개 화면 전체를 돌려 24개 통과, 실패 0, 검사 불능 0. G-11 1440·1280 화면 그림은 메인이 직접 봤다(다섯 칸, 승인 PR 칸과 승인할 PR 줄이 있음).
- `test_console_mockup_compare.py` 5 passed. 그중 첫 시험은 빌려 오기 없이 다섯 칸 화면이 앞 시안에 실패하는 것을 확인한다.

## 판 번호
배포되지 않는 시험 도구(`checker/tests/`)와 문서만 바꿔서 plugin.json version 은 올리지 않는다.
