# #733 웹 콘솔 문제·해결 기록 화면 (G-20 목록 · G-21 한 건 · G-22 새 기록)

## 한 일

- `console/trouble.py`(새 파일): 콘솔이 아는 작업 폴더(known_roots)의 GitHub 저장소에서 `type:trouble` 이슈를 gh 로 읽고 쓴다.
  - 읽기: `GET /api/trouble`(목록·필터 status/stage/q/project/author·통계, 60초 기억, 못 읽은 저장소는 `ok:false` + 사유로 따로), `/api/trouble/item`(본문 칸 파싱 + 댓글 이력 종류 분류 + 관련 PR + 비슷한 기록), `/pr`(PR 번호 확인), `/similar`, `/draft`.
  - 쓰기(POST, 사람이 단추를 눌렀을 때만): `/api/trouble`(이슈 만들기 — 제목 머리말 `[기록] `, 라벨 `type:trouble`, 양식 칸 그대로), `/comment`(`시도·안 됨:` / `해결 후보:` / `해결:` 표시), `/resolve`("이걸로 해결": 본문 해결 방법 갱신 → 댓글 → 닫기), `/check`(비밀정보 검사), `/draft`(AI 초안 저장, 메모리 20개).
  - 안전: 저장소는 known_root 의 것만(403), 기록 라벨이 없는 이슈엔 쓰지 않음(404), 라벨이 저장소에 없으면 라벨 없이 올리지 않고 만드는 명령을 안내(409, 라벨은 만들지 않는다), 비밀번호·키처럼 보이는 줄이 있으면 올리지 않음(422, 서버에서 한 번 더 검사), gh 실패는 "확인 못 함" + 사유(기록 없음과 구분).
  - 일부만 된 쓰기(이슈는 올랐는데 댓글·닫기 실패)는 `warnings` 로 알린다.
- `server.py`: 라우트 10줄, `tb()` 오류 변환, SPA 경로(`/troubles`, `/troubles/new`, `/troubles/:owner/:repo/:n`).
- `static/trouble.js`·`trouble.css`(새 파일), `index.html`·`app.js` 는 라우트·헤더 메뉴 "기록"·모듈 연결 몇 줄만.
- 시험: `checker/tests/test_trouble_console.py`(gh 흉내 API 10개 + node 화면 시험).
- plugin.json 0.10.208, `whats_new.json`, 설계 문서 §2·§8·§9, 길잡이 콘솔 설명.

## 판단과 한계

- 풀림 = 이슈가 닫힘. `해결:` 댓글만 있고 열려 있으면 아직으로 센다.
- 실제 GitHub 에서는 확인하지 못했다(진짜 저장소에 이슈를 만들지 않는다는 규칙). gh 호출 모양(`issue list/view/create/comment/edit/close`, `label list --search`, `pr view`)은 흉내 gh 로만 시험했다.
- 비슷한 기록은 제목+증상 첫 줄의 두 글자 조각 겹침(Dice 0.3 이상)이다. 형태소 분석은 하지 않는다.
- 비밀 검사는 이름=값 꼴(secret·password·token·key 등), 알려진 토큰 꼴, 개인 키, JWT, 주소의 비밀번호만 본다. 소문자 12자 이하 낱말 값(`token: expired`)과 가린 값(`••••`)은 걸지 않는다.
- "나중에 쓰기"는 이 브라우저(localStorage)에만 저장한다. AI 초안은 서버 메모리에만 두고 재시작하면 사라진다.
- 세션 화면의 "기록하기"(G-23, #734)와 홈의 팀 기록 타일(G-24, #735)은 이번 범위가 아니다. 초안 API(`POST /api/trouble/draft` → `/troubles/new?draft=id`)는 #734 가 쓸 수 있게 열어 두었다.
- 시안과 다른 점: 숫자 띠의 노랑 숫자에 앱 공통 약속 `! ` 표시가 붙는다(shape cue). 목록 단계 필터는 API 에만 있고 시안에 없는 화면 단추는 만들지 않았다.

## 리뷰 지적 반영

- 비밀 검사: 이름 뒤 따옴표(`"password": "..."`), 따옴표 안 값 전체(`password: "my secret pass"`), 짧은 소문자 값(`password: letmein`)도 걸린다. 가린 값(`••••`·`<값>`)만 통과. 단독 키 꼴에 `sk-…`·`github_pat_`·Slack 토큰을 더했다(`ghp_`·`AKIA…`는 이미 있었다). 꼴마다 시험.
- 본문 칸: 증상은 내용보다 긴 코드 펜스로 감싸 올리고, 읽기·`replace_solution` 은 코드 펜스 안의 `### ` 줄을 칸 머리로 보지 않는다. "이걸로 해결" 뒤에도 증상이 그대로인 것을 시험.
- 쓰기 시간 초과·실행 불능(127, 출력 없음)은 504 "올렸는지 확인 못 함 — 목록을 새로고침해서 확인해 줘"(등록은 같은 제목 기록이 생겼는지 먼저 보라는 안내 포함). 목록 기억도 비운다. 화면은 보라 `? 올렸는지 확인 못 함` + `목록 보기`, 그 밖 실패는 빨간 `✕ 올리지 못했어`.
- 한 건 화면: 목록을 못 읽었으면(`similarOk:false`) 비슷한 기록을 "확인 못 함"으로, 새 기록 화면도 `/similar` 실패·`ok:false` 면 같다. PR 이 저장소에 없으면(`missing`) "찾지 못했어" 글만(확인 못 함 아님).
- 이슈 100건에 닿으면 `projects[].truncated`·`stats.truncated`·`stats.limit` 으로 알리고 화면 제목 줄과 푸터에 "최근 100건만 읽었어".
- 같은 origin 의 worktree 는 하나로 묶어 `gh repo view` 를 한 번만 부르고, 못 읽은 결과는 10초 뒤 다시 읽는다(60초 기억에 가두지 않음).
- 초안 id 는 `d-` + uuid 12자리, 보관은 잠금 안에서. "PR 화면에도 자동으로 연결돼" 문구는 #734 전까지 뺐다. 초안 읽기 실패는 글로 알린다. 나중에 쓰기는 비밀 검사에 걸린 상태면 저장하지 않고 이유를 보인다.
- 한계: PR 제목 목록(100건)이 잘려도 표시하지 않는다(PR 이름만 빠질 뿐 기록은 그대로).
