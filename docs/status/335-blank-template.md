# #335 고객 견본에서 빈 양식 만들기 — PR A 견본 지우기 (2026-10-15)

고객사 견본 xlsx 에 지도 밖 샘플(셀 값, 그림·도형, 다른 고객사·사내 서버를 가리키는 외부 참조)이 섞여 있어 템플릿으로 그대로 못 쓴다. 분할: A 견본 지우기(이 PR) → B 남은 견본 검사(`견본_검사`·`유지`) → C1 셀 서식·병합 쓰기 → C2 화면 md 문법과 그리기.

## 바뀐 것

- 새 모듈 `checker/blank_template.py` + CLI `python -m checker.blank_template --root R --form F --src 견본 --out 빈양식 [--check]`. `--out` 이 있으면 거부.
- 지도 키(시트): `비우기: [범위…]`(값만 지움, `SheetXml.clear_range` 재사용), `그림_지우기: true`, `유지: [범위…]`(키만 인정). 최상위 `외부_참조_지우기: true`.
- 쓰기는 zip 수준(openpyxl 저장 안 함). 바뀐 파트 말고는 바이트 그대로 → x14 드롭다운 시트 보존.
- sharedStrings: 지운 칸이 가리키던 `<si>` 중 더는 아무 칸도 안 가리키는 것만 `<si><t/></si>` 로 비움(번호 유지, `count` 조정).
- 그림 지우기: 시트 XML 의 `<drawing>`·`<picture>` 제거 → 시트 rels 에서 drawing 관계만 제거(printerSettings 유지, 관계가 비면 rels 파트 삭제) → 아무도 안 쓰는 drawing·drawing rels 삭제 → media 는 남은 rels 가 가리키지 않을 때만 삭제(참조 수 세기) → `[Content_Types].xml` Override 정리. 차트·도식·삽입 개체를 가리키는 drawing, 시트의 legacyDrawing·oleObjects·controls 는 지원 안 함(2).
- 외부 참조 지우기(사용자 결정 추가): externalLinks 파트·rels, `workbook.xml` 의 `externalReferences`, workbook rels, Content_Types, `[N]` 을 쓰는 이름 정의 삭제. 그 이름이나 `[N]` 을 쓰는 데이터 유효성(표준·x14)·셀 수식·조건부 서식·차트·표 수식이 있으면 지우지 않고 위치를 밝히며 2. `#REF!` 이름은 외부 참조가 아니라 그대로 두고 알림.
- `비우기` 는 지도의 칸·표(`시작_행`~`최대_행`, 없으면 끝까지)·서술·`유지` 범위와 겹치면 지도 오류(2). 검증 함수 `blank_template.map_problems` 를 `export.load_map` 과 `form_columns._valid_map` 이 같이 쓴다.
- `export.py`: 산출 때도 지도 `비우기` 를 적용(안전망, 공유 문자열 정리 포함). 기존 `해당 없음` 경고 블록은 그대로(PR B 에서 대체).
- 서술 두 칸 결함 수정: 서술 항목에 `열: {제목: D, 설명: E}` 를 두면 md 줄 `제목 | 설명` 을 각 칸에 쓴다(설명 안 줄바꿈은 `<br>`, `|` 없는 줄은 제목만). `열` 이 없으면 기존 한 칸 동작. 열은 위치의 열 범위 안이어야 한다.
- 문서: `form-map.md`(새 키·CLI), spec `SKILL.md`("비우기 로 지운다"). Plugin version 0.10.75 → 0.10.76.

## 후속: 채울 자리의 견본 지우기 (2026-10-15, Plugin 0.10.77)

public-cloud 개발사양서 빈 양식을 만들었더니 지도의 칸·표·서술 자리에 견본(CO-001 값)이 그대로 남았다. `비우기` 가 그 자리와 겹치면 지도 오류라 지울 수 없었다. 원칙: 템플릿은 견본이 없는 빈 양식이다.

- **기본 동작.** 지도 키 없이, 빈 양식은 지도가 "채울 자리" 로 정한 곳의 값을 지운다: 칸 `위치`(`자동` 칸 제외), 표 데이터 영역(머리글 행 제외, 열마다, `최대_행` 없으면 값이 이어지는 마지막 행까지), 서술 범위(두 칸 `열` 이어도 범위 전체). 라벨·머리글·작성 안내문은 지도가 맡지 않은 칸이라 남는다.
- **export 와 같은 함수.** `export.fill_ranges(ed, 시트지도)` 와 `export.table_template_last(ed, 표)` 를 새로 두고 빈 양식이 쓴다. `_write_table` 의 템플릿 데이터 영역 계산도 같은 함수로 바꿨다. 그래서 "빈 양식 = 산출이 아무 값도 안 넣었을 때의 모습" 이고, 테스트가 두 결과의 셀 값을 비교한다.
- **export 동작 변경 하나.** 값이 없는 칸은 `예시` 가 없어도 템플릿 샘플을 비운다(전에는 `예시` 가 있는 칸만). 빈 양식과 어긋나지 않게 하려는 것이다. `자동` 칸은 그대로 건드리지 않는다. 지도에 `고정` 이라는 키는 정의돼 있지 않아 따로 다루지 않았다(`자동` 만 안 건드린다).
- **`유효성_지우기: [범위…]`**(시트 항목). 그 범위와 겹치는 데이터 유효성을 표준·x14 모두에서 뺀다. 한 항목의 `sqref` 가 일부만 겹치면 겹친 부분만 빼고 나머지는 남긴다(직사각형 빼기). 다 빠진 항목은 지우고 `count` 를 고치고, 비게 된 묶음과 x14 `ext`·`extLst` 도 걷는다. 외부 참조 판정보다 먼저 처리해 외부 이름을 쓰던 드롭다운을 이 키로 빼면 `외부_참조_지우기` 와 충돌하지 않는다(테스트). 보고에 `validations_cleared`. 열 전체 `A:A` 같은 `sqref` 는 해석하지 않고 두고 `notices`(`validation-unparsed`)로 알린다. 범위 모양 오류는 지도 검증(`map_problems`)이 막는다(blank_template 1, export·form_columns 쪽은 기존 규칙).
- **시트 이름 알림.** `review-needed`/`sheet-names` 는 지도 `시트` 이름과 같은 시트를 뺀다(지도가 이름을 정한 시트는 견본이 아니다). 지도에 없는 시트만 남으면 그것만 알린다.
- 테스트: `test_blank_template.py` 에 칸·표·서술 견본 제거와 라벨 보존, 산출과 빈 양식의 빈 상태 일치, `fill_ranges`, 유효성 부분 겹침(표준·x14)·전부 제거, 외부 참조와의 순서, 범위 오류, 시트 이름 알림. 기존 픽스처의 칸 위치를 라벨 칸(A1)에서 값 칸(F1)으로 옮겼다(A1 은 라벨이라 지도가 맡으면 안 된다).
- 문서: `form-map.md`(기본 동작, `유효성_지우기`, 산출의 빈 칸 처리), Plugin version 0.10.76 → 0.10.77.

### 서식 지우기 (PR #340 추가)

값만 지운 빈 양식을 엑셀로 열면 Display Screen 의 견본 목업 표 테두리·하늘색 머리글 채우기·회색 버튼 칸 서식이 빈 표 모양으로 남았다. 이것도 견본이다.

- 시트 키 `서식_지우기: [범위…]`: 값 지우기에 더해 셀 `s` 를 열 기본 서식(`<col style>`, 없으면 0)으로 되돌리고 범위 안에 통째로 든 병합을 푼다. `styles.xml` 은 그대로. `비우기` 와 같이 쓸 수 있다.
- 오류: 범위 모양 오류는 지도 오류, 칸·표·서술·`유지` 와 겹치면 지도 오류, 범위 안 수식 셀과 병합이 일부만 겹침은 종료코드 2.
- 조건부 서식 판단: sqref 가 범위 안에 통째로 들면 뺀다. 일부만 겹치면 sqref 를 잘라 시작 칸이 바뀌면 상대 참조가 틀어지므로 고치지 않고 `conditional-format-overlap` 로 알린다.
- 테스트(`test_blank_template.py`): 테두리·채우기 셀이 기본 서식으로 돌아감, 병합 제거와 범위 밖 병합 유지, 열 기본 서식 존중, 부분 병합 겹침 2, 수식 셀 2, `유지` 겹침 오류와 `비우기` 병용, styles.xml 바이트 동일.
- 사용자가 엑셀에서 열어 복구 창이 뜨지 않음을 확인했다(이전 판). 서식까지 지울 곳은 Display Screen 목업 두 영역뿐이다.
- public-cloud 원본 템플릿 Display Screen 의 테두리·채우기 셀을 읽어 정한 범위(고객 지도, 저장소 밖): 위 표 3개 `C10:G14, I10:M14, O10:S14`, 아래 하늘색 라벨 칸 `C43, I43, O43, V43`, 회색 버튼 칸 `D45:E45, J45:K45, P45:Q45, V45:W45`, 표 4개 `C47:G51, I47:M51, O47:S51, U47:Y51`. 이 밖에 테두리·채우기 셀은 없다(기존 `비우기` C7:S14·C43:Y51 보다 좁다. 7~9행·44·46행에는 서식이 없었다). 서술 D17:E33·D54:E74 와 L2·L38 서식은 건드리지 않았다. 병합은 이 시트에 없다. Initial Screen 은 B3:B13 에 테두리 칸 틀(목록 칸)이 남아 있다(지우지 않음, 사용자 판단 대기).

## PR C1 셀 서식·병합 쓰기 기반 (Plugin 0.10.78)

사용자 결정: 개발사양서 화면 시트(Initial Screen, Display Screen)에 Spec 의 화면 구성(조회 조건·버튼·결과 표)을 셀·테두리·채우기·병합으로 그려 넣는다. 색·테두리·글꼴은 지도(Project Repository 의 데이터)가 정하고, 엔진은 `styles.xml` 에 항목을 덧붙인다. C1 은 그 기반이고 export 흐름에는 아직 잇지 않았다(사용자 동작 변화 없음, 길잡이 안 고침). 화면 md 문법 해석과 실제 그리기, 지도 `화면:` 절은 C2.

- 새 모듈 `checker/cell_style.py`. openpyxl 로 저장하지 않고 XML 만 고친다.
- **스타일 정의**(한국어 키 dict): `채우기`(RRGGBB 또는 `없음`), `테두리`(얇게·중간·굵게·없음, 네 변), `테두리_색`, `굵게`, `글꼴_크기`, `글꼴_색`, `가로`(왼쪽·가운데·오른쪽), `세로`(위·가운데·아래), `줄바꿈`. 적은 키만 덮어쓰고 나머지는 셀의 기존 서식(글꼴 이름·숫자 형식 등)을 따른다. `validate_style(defn) -> list[str]` 가 모르는 키·잘못된 값·빈 정의·`테두리_색` 단독 사용을 사유로 돌려주고, 쓰는 함수는 정의가 틀리면 `ExportError` 로 멈춘다(조용히 무시하지 않음).
- **`StylesXml`**: fonts·fills·borders·cellXfs 에 항목을 덧붙이고 같은 항목은 재사용, `count` 갱신. `derive(base_xf, 정의) -> xf 번호`는 기존 xf 를 바탕으로 정의에 적힌 부분만 덮어쓴 새 xf 를 만든다(글꼴은 기존 글꼴에서 굵게·크기·색만 바꾸고, 정렬은 기존 속성 위에 합침). 안 건드린 섹션(dxfs·cellStyleXfs·numFmts 등)은 바이트 그대로.
- **시트**: `SheetXml.set_style(ref, s)`(행·셀이 없으면 열 순서대로 만들고 dimension 만 넓힌다. 값·자동 필터는 안 건드림), `cell_style.style_range(ed, styles, 첫칸, 끝칸, 정의, 시트이름)`(칸마다 기존 s, 없으면 행 기본·열 기본 서식 위에 덮어씀), `merge_range(ed, 첫칸, 끝칸, 시트이름)`(`mergeCells` 가 없으면 스키마 순서 자리에 만들고 count 갱신), `merges_of(ed)`.
- **멈춤 규칙**: 새 병합이 기존·이전 병합과 한 칸이라도 겹치거나 한 칸짜리이거나 왼쪽 위 아닌 칸에 값이 있으면 `ExportError`(쓰지 않음).
- 판단: 테두리는 범위의 **모든 칸 네 변**으로 시작(바깥선만 그리는 모드 없음). 병합 칸의 테두리를 바깥선으로 보이게 하려면 병합 범위 전체에 `style_range` 를 먼저 쓴다(엑셀도 병합 칸 전체에 서식을 둔다).
- **검토 반영.** (1) 읽지 못하는 기존 병합(`ref` 없음·모양 오류·mergeCells 안 알 수 없는 내용·닫히지 않은 태그)이 있으면 겹침 검사를 건너뛰지 않고 검사 불능으로 `ExportError`. (2) 바탕 서식: 셀 요소가 이미 있으면 `s` 가 없어도 엑셀 규칙대로 xf 0 위에 덮어쓴다(열·행 기본 서식을 따르지 않음). 셀을 새로 만들 때만 행(`customFormat` + `s`) → 열 기본 서식 순이며 행이 우선이다. (3) `<mergeCells count="0"/>` 같은 self-closing 을 인식해 교체한다. (4) styles.xml 의 작은따옴표 속성도 읽고, 읽지 못한 속성 조각이 남으면 `ExportError`(말없이 버리지 않음). (5) `style_range` 는 모든 칸의 xf 를 먼저 정한 뒤에만 시트를 바꾸고, 실패하면 이번 호출이 덧붙인 styles 항목도 되돌린다(`StylesXml.snapshot/rollback`). cellXfs 가 엑셀 한도 64000 에 닿으면 `ExportError`.
- 테스트: `checker/tests/test_cell_style.py`(xf 추가·재사용, 기존 xf 기반 덮어쓰기, 없는 행·셀 서식과 열 순서, 열 기본 서식 위 덮어쓰기, 병합 추가·mergeCells 생성 위치·겹침·값 있는 칸 거절, 잘못된 정의 거절 17종, 결과 xlsx 를 openpyxl 로 열어 서식·병합 확인, 다른 파트 바이트 동일).
- 확인하지 못한 것: 엑셀로 열어 복구 창 여부(openpyxl 로 열림과 XML well-formed 만 확인). 행 단위 서식(`<row s customFormat>`)은 새 셀의 바탕으로만 읽고 쓰지 않는다. 테마 색·인덱스 색은 쓰지 않는다(RRGGBB 만).
- 남은 일(C2): 화면 md 문법 해석, 지도 `화면:` 절(스타일 이름 → 정의, 영역 초과 검사), export 연결, 서술 키 `위치` 와 겹치는 영역 처리.

### 사용자 결정 반영: Fiori 용어와 배치 (PR #344)
근거(SAP 공식: Fiori Design Guidelines·SAPUI5·help.sap.com): Public Cloud(ABAP Cloud)의 UI 는 SAP Fiori 뿐이라 ALV 를 쓰지 않는다. List Report 는 한 페이지에 필터 바(header)와 테이블(content)이 같이 있고, 버튼은 테이블 위 table toolbar 의 액션이다. 첫 진입 조회는 live(권장, 필터를 바꾸면 바로 조회)와 manual(Go 버튼)로 나뉜다. Initial Page floorplan 은 객체 1건으로 바로 들어가는 용도라 목록이 나오면 쓰지 말라고 돼 있다. 한국어 공식 번역은 "테이블", "스마트 필터 바", "액션".

- **용어.** md 소절 `조회 조건`→`필터 바`, `버튼`→`액션`, `결과 표`→`결과 테이블`. 지도 `칸_수`·`스타일` 키도 `버튼`→`액션`. 옛 이름은 받지 않는다(배포 전이라 호환 없음). 표 머리는 그대로(`이름 | 필수`, `이름`, `열`). 예시의 `[ALV]` 는 `[결과 테이블]`.
- **배치.** 액션은 결과 테이블 머리글 바로 윗줄(table toolbar)에 영역 오른쪽 끝에 붙여 오른쪽 정렬(마지막 액션이 영역 마지막 열에서 끝남). 결과 테이블이 없으면 필터 바 뒤 빈 줄 다음 줄에 같은 오른쪽 정렬. 액션이 영역 너비를 넘으면 거부. 필터 바와 다음 사이 빈 줄 1은 그대로.
- **조회 방식.** `#### <이름> 그림` 바로 아래 선택 `| 항목 | 값 |` 표. 키는 `조회` 하나, 값은 `자동`(기본)·`Go`. `Go` 면 필터 바 마지막 줄 영역 오른쪽 끝에 `Go`(액션 스타일·칸 수), 자리가 없으면 다음 줄 오른쪽 끝, 영역을 넘으면 거부. 모르는 키·값·머리글·중복 키는 `offenders` 가 거부(2, form_columns 도 같은 검사).
- **Initial Screen.** 코드에 시트 이름이 없다(원칙 2). 시트가 `해당 없음` 이면 "그림 절이 없어 그리지 않았다" 경고를 내지 않는다(의도된 생략). 해당 없음이 아닌데 그림 절이 없거나 작업본에 시트 절 자체가 없으면 경고한다. form-map.md·SKILL.md·길잡이에 "List Report 는 Display Screen 화면 1 에, Initial Screen 은 Initial Page 일 때만, 그 밖엔 해당 없음" 안내를 넣었다.

- **사용자 결정(안내 문구).** Initial Screen 은 설계자가 요청할 때만 그린다(예: 단건 진입 앱). 요청이 없으면 Spec 의 Initial Screen 절은 `해당 없음`, 산출물엔 빈 양식을 그대로 둔다. 안 쓰는 시트·영역(예: 화면 2)을 숨기는 방안을 검토했지만 숨기거나 지우지 않고 그대로 두기로 했다.

## PR C2 후속: 표 서식 행 복제 (Plugin 0.10.80)

개발사양서 Public Logic 표에서 템플릿 서식(이벤트 묶음 테두리)이 빠지던 결함. 원본 견본은 병합 없이 이벤트마다 테두리로 상자를 쳤다(첫 행 위·좌·우, 중간 좌·우, 끝 아래·좌·우, 한 행짜리 네 변).

- **원인.** `table_template_last` 는 값을 기준으로 템플릿 데이터 마지막 행을 정한다. 값을 지운 빈 양식에서는 `시작_행-1` 을 돌려줘 `_write_table` 의 복제 원본이 `None` 이었고, 템플릿 행보다 늘어난 새 행은 서식과 행 속성 없이 만들어졌다(테두리 끊김). 템플릿 3~14행에 남은 샘플 서식은 산출 내용과 맞지 않았다(13행 아래 선이 이벤트 중간에 그어짐).
- **사용자 결정(B 방식).** 지도(데이터)에 서식 행을 적고 블록마다 그 행의 서식을 복제한다. 표 선택 키 `서식_행: {첫, 중간, 끝, 한_행}`(행 번호) + `묶음_열`(열 문자), 둘은 같이 쓴다. 코드에 시트·열 이름은 없다.
- **동작.** `묶음_열` 에 값이 있는 행에서 묶음이 시작하고 다음 시작 전까지다. 첫 데이터 행에 값이 없으면 첫 행부터 첫 시작 전까지가 한 묶음이다. 한 행짜리는 `한_행`, 아니면 `첫`·`중간`…·`끝`. 표의 모든 열 셀 서식(`s`)과 행 서식(`s`·`customFormat`)을 서식 행에서 복제하며 값이 빈 칸·늘어난 새 행에도 적용한다. 높이(`ht`)·숨김은 복제하지 않는다(새 행의 행 속성은 전과 같이 복제 원본 행에서 오고 `autofit`·줄 높이 어림도 그대로).
- **남는 템플릿 행.** 산출 행이 템플릿 행(시작_행 ~ 서식 행 최대값과 값 기준 마지막 행 중 큰 쪽)보다 적으면 남는 행의 값을 지우고 셀 서식을 열 기본 서식(`<col style>`, 없으면 0)으로 되돌린다(`서식_지우기` 와 같은 결과, 병합 해제·행 서식 변경은 안 함). 값 없는 행에 상자 테두리가 남지 않는다.
- **`서식_행` 없는 표.** 예전 동작 그대로. 단 빈 양식 결함은 고쳤다: 값 기준 마지막 행이 없으면(`tmpl_last < 시작_행`) 시작 행에 서식 있는 셀이 있을 때 그 행을 복제 원본으로 쓰고, 이미 있는 셀은 서식을 덮어쓰지 않는다(템플릿 행이 자기 서식을 지킨다). `table_template_last` 자체는 바꾸지 않았다 — `fill_ranges`(산출의 비우기와 빈 양식)와 파일명 자리가 같은 함수를 쓰기 때문이다.
- **검증.** `blank_template.map_problems` 가 `서식_행` 네 키·정수·`시작_행` 이후·`최대_행` 범위 안, `묶음_열` 이 표 `열` 의 문자인지, 둘이 같이 있는지를 본다(산출 `load_map` 과 `form_columns` 가 같이 씀 → 지도 오류 2). 템플릿에 서식 행 셀이 없거나 `s` 가 없으면 산출이 멈춘다(2).
