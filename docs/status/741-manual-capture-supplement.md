# #741 매뉴얼 캡처 뒤 설명 보충 단계

## 배경
캡처(`checker.manual_capture`)는 그림과 `#### 번호 설명` 을 목록(`capture.yaml`)의 `설명` 으로 바꿀 뿐 `기능 설명` 은 건드리지 않는다.
개발하면서 화면이 달라지거나 항목이 생겨도 사람이 직접 찾아 고쳐야 했다. 매뉴얼을 먼저 쓴 사람도 나중에 쓴 사람도 개발 뒤에는 캡처를 거치므로 두 갈래 모두에 필요하다.
매뉴얼 먼저 쓰기·시험 흐름 4건 중 첫째다(#741 설명 보충 → #742 pptx 읽어 들이기 → #743 조회 시험 → #744 끝까지 시험).

## 바꾼 것
- `plugins/harness/skills/manual/SKILL.md` 캡처 절에 "6. 설명 보충" 을 더했다(5 다음, 산출 앞). `ok` 로 끝난 화면마다 새 그림을 Read 로 보고 `기능 설명`·번호 설명·`표시` 와 맞대
  빠짐·달라짐·확인 필요를 화면별 표로 보이고, 사용자가 AskUserQuestion 으로 고른 것만 반영한다. 5 절 끝의 "산출로 간다" 문장은 새 절 끝으로 옮겼다.
- `docs/guide/harness-guide.html` 매뉴얼 탭 "내가 할 일" 에 li 하나.

## 판단
- 문서만 바꾸고 코드는 바꾸지 않았다. 그림 대조는 Claude 가 하고 사람이 확인한다. 그림만으로 판단할 수 없는 것은 고친 안을 쓰지 않고 "확인 필요" 로 남겨
  검사를 못 한 것을 맞음으로 뭉개지 않는다(`CLAUDE.md` 7번).
- 번호 설명을 고치면 `capture.yaml` 의 `설명` 도 같은 문장으로 맞춘다. 안 맞추면 다음 캡처가 목록 문장으로 덮어 되돌린다.
- 빠진 항목은 작업본에 번호 설명만 더하지 않고 `표시` 에 더해 그 화면만 다시 캡처한다(그림의 번호와 어긋나지 않게).
- `workflow.json` 의 manual 근거 `quote` 는 스킬 description 문장이라 이번 변경과 무관해 그대로 뒀다.
