# #744 매뉴얼 쓰기 시험 흐름 (2026-11-11)

## 배경
#743 의 확인은 조회 화면만 다뤘다. 실제 업무 흐름(대상 앱: public-cloud 생산실적 모니터링 `#ZPP_AUTO1_PRODUCT_STATUS-display`, sap.ui.table GridTable 다중 선택)은
행을 골라 취소 버튼을 누르면 `sap.m.MessageBox.confirm` 이 뜨고, 확인하면 표가 새로고침되며 MessageToast("취소 완료 N건, 실패 M건…")가 잠깐 뜬다. 실패하면 `MessageBox.error`.
엔진은 준비 단계 뒤 대화상자를 모두 검사 불능으로 쳤고(MessageBox 는 alert 취급) 행 선택도 단계로 없었다.

## 한 일
`checker/manual_capture.py`·`checker/manual_capture_js.py`.

- 화면 키 `바꿈: true`(bool). `창 누르기` 단계는 `바꿈: true` 화면에서만 허용(아니면 `ListError`). `바꿈` 인데 `창 누르기` 가 없는 것도 허용.
- 새 준비 단계: `{행 고르기: <열>, 행: N}`(행 선택 칸을 실제 마우스 클릭, 뒤이어 선택 확인), `{창 누르기: <버튼 글자>}`(대화상자 정확히 하나 안의 같은 글자 버튼 하나를 클릭).
- `누르기` 뒤 다음 단계가 `창 누르기` 면 대화상자 1개(alert 포함)를 허용한다. 그 밖은 예전 규칙.
- `--allow-write` 없음 = 연습: 첫 `창 누르기` 앞까지 돌고 그 버튼이 있는지만 확인한 뒤 그 상태를 찍고, Cancel·취소 버튼(없으면 Escape 대신 `Page.reload` 뒤 `wait_ready`·도구 함수 다시 주입)으로 닫는다. 화면 상태 `멈춤`, 사유 "쓰기 허락(--allow-write) 없이 데이터를 바꾸는 단계 앞에서 멈췄다. …닫은 결과". 작업본은 고치지 않는다.
  `창 누르기` 가 없는 `바꿈` 화면은 브라우저를 건드리기 전에 `멈춤`("어디서 멈출지 몰라 실행하지 않았다").
- `멈춤` 화면이 있으면 전체 `status` 는 `incomplete`(종료 1). 바꿈 화면이 있으면 결과에 `쓰기: 연습|허락`.
- `--allow-write` 에서 첫 `창 누르기`(클릭 직전에 표시) 뒤 검사 불능·미완이 된 화면은 `데이터 바뀜: true` 와 사유 앞 "데이터가 바뀌었을 수 있다 — ". 완료여도 `데이터 바뀜: true`. `창 누르기` 뒤에 대화상자가 남으면 검사 불능(창 글 포함).
- 알림: 바꿈 화면이거나 `{알림}` 확인이 있는 화면은 준비 단계 중(각 단계 직후·`wait_ready` 반복마다) `.sapMMessageToast` 글만 모아 화면 행 `알림` 에 낸다(중복 없이, 나타난 순서). `{알림: 글}` 확인 — 포함하면 `맞음`, 없거나 하나도 못 모았으면 `다름`(실제: 모은 목록), 읽기 실패는 `검사 불능` — 단 `CdpError` 한 번은 다음 기회에 다시 읽고 같은 화면에서 연속 2회 실패할 때만 그렇다.
- 기록: `{열, 행}`(값 없음) → 결과 `기록`, `실제` 에 칸 값. 판정·status 영향 없음. `{열}` 만은 여전히 거부. opaque·못 찾음은 검사 불능.
- JS: `rowSelector`·`rowSelected`·`dialogButton`·`toasts`.
- `/harness:manual` 에 새 키·단계·확인 형식·결과 설명과 새 소절 "쓰기 시험"(사용자에게 테넌트·흐름·생긴 문서 처리 먼저 묻기 → 연습 → 허락 → `--allow-write` 한 건 → 결과 표). 길잡이 매뉴얼 탭·`checker/README.md` 도 맞췄다.
- 검토 지적 반영: ① 쓰기 뒤 그림 저장 실패(`OSError`)를 화면 단위로 잡아 `검사 불능`+`데이터 바뀜` 행을 만들고 다음 화면으로 계속하며, 그 밖에 바깥 `except` 로 빠진 예외도 쓰기 뒤면 problems 문장 앞에 "데이터가 바뀌었을 수 있다 — " 와 화면 이름을 남긴다.
  ② 첫 `창 누르기` 바로 앞 단계는 `누르기` 여야 한다(파서 `ListError`). 그 `누르기` 뒤 대화상자가 정확히 하나 아니면 연습이어도 검사 불능·`데이터 바뀜: true`. ③ 행 선택 칸 후보는 `.sapUiTableRowSelectionCell`·`[role=rowheader]` 둘뿐.

## 판단
- 연습 모드의 `멈춤` 그림은 표시를 못 찾으면 예전처럼 `_미완` 이름으로, 다 찾으면 정식 이름으로 저장하되 작업본은 고치지 않는다(끝까지 돈 그림이 아니다).
- 연습에서도 첫 `창 누르기` 의 버튼이 있는지(대화상자 하나·버튼 하나)는 확인한다 — 누르지는 않는다. 그래야 연습이 "창 찾기 확인" 이 된다.
- `창 누르기` 뒤에 대화상자가 남으면 종류와 상관없이 검사 불능이다(오류·경고 창이면 그렇게 말한다). `창 누르기` 를 연달아 쓰는 흐름은 두 번째 확인 창을 알려진 오류 창과 가릴 수 없어 아직 허용하지 않는다.
- `창 누르기` 가 없는 `바꿈` 화면이 `--allow-write` 로 돌 때는 `누르기` 자체가 쓰기일 수 있어 그 단계를 누르기 직전에 `데이터 바뀜` 대상으로 친다.
- 연습이 안전한 것은 확인 창을 거치는 흐름뿐이다. 버튼 하나가 바로 저장·전기하는 흐름은 연습도 데이터를 바꾸므로 쓰지 않고, 그런 버튼이 `창 누르기` 바로 앞 `누르기` 가 아닌지는 사람이 확인한다(도구는 확인 창이 안 뜬 것으로만 알 수 있다).
- 행 선택 칸 안의 체크박스는 그 칸을 누르면 된다고 보고 `[role=checkbox]`·`.sapMCb` 를 후보에서 뺐다. 행 안 다른 칸의 체크 상태는 선택 판정에 쓰지 않는다.
- 알림은 `알림` 키를 바꿈 화면이나 `{알림}` 확인이 있는 화면에만 낸다(그 밖의 목록 결과는 예전과 같다). 준비 단계가 하나도 없으면 모으지 않는다.

## 실측으로 찾은 것(Z5U/100 생산실적 모니터링, `--allow-write`)
- 행 선택 칸은 본문 행 밖의 `…-rowselK` 칸이었다(커밋 bc6fb48 에서 후보 찾기를 고쳤다).
- MessageBox 버튼의 글자는 `확인`·`취소` 였다(`OK`·`Cancel` 아님).
- `창 누르기`(확인) 뒤 앱이 서버 액션을 최대 4번(1초 간격) 재시도하는 동안 가운데에 UI5 전역 BusyIndicator 가 보통 1초 지연 뒤 뜬다. 엔진은 그 전에 두 번 연속 준비 상태로 보고 통과해 처리 중에 확인·캡처를 했고, 결과가 "완료"(+데이터 바뀜)였다. 몇 초 뒤 실제로는 `MessageBox.error("API 호출에 실패 하였읍니다.")` 가 떠 있었다. 이번 수정:
  - `READY_JS` 가 화면에 보이는(`offsetWidth`·`offsetHeight` > 0) `#sapUiBusyIndicator`·`.sapUiLocalBusyIndicator`·`.sapUiBusy` 도 막는 것으로 본다.
  - `창 누르기` 직후에는 `settle_after_write()` 가 최소 3초는 준비 상태여도 끝내지 않고, 그 뒤 0.5초 간격 연속 3회 준비 상태일 때 끝낸다. 상한은 `--timeout`(최소 5초). 넘으면 검사 불능 + `데이터 바뀜`, 사유 "쓰기 뒤 처리 중 표시가 사라지지 않았다". 기다리는 동안에도 토스트를 읽는다. 그 뒤 남은 대화상자 판정은 그대로다.
- 앱 쪽 결과: 확인 121 취소 시 "API 호출에 실패 하였읍니다." 오류 창이 떴고, 상태·Message 칸은 비어 있고 토스트는 없었다. 원인은 앱 쪽이라 public-cloud 이슈로 넘긴다.

## 확인 못 한 것
- 아래 중 행 선택 칸·버튼 글자는 위 실측으로 확인됐다. 나머지는 가짜 탭 시험만 했고 추측이다.
  - 행 선택 칸이 `.sapUiTableRowSelectionCell`·`[role=rowheader]` 중 무엇인지(둘 다 아니면 검사 불능), 같은 `aria-rowindex` 로 본문 칸과 이어지는지, 선택 뒤 `aria-selected="true"`·`aria-checked`·`.sapUiTableRowSel` 이 그 칸에 실제로 켜지는지.
  - MessageBox 버튼의 한국어 글자(`OK`·`Cancel` 인지 `확인`·`취소` 인지). 연습은 `Cancel`·`취소` 순으로 찾고 없으면 페이지를 새로 읽어 닫는다(새로 읽은 뒤 Launchpad 상태가 어떤지는 실제 테넌트에서 못 봤다).
  - `창 누르기` 앞 `누르기` 의 첫 클릭부터 `wait_ready` 가 시간 초과로 실패하는 경우(확인 창 판정까지 못 간 경우)는 `데이터 바뀜` 으로 치지 않는다.
  - MessageToast 의 클래스(`.sapMMessageToast`)와 토스트가 `wait_ready` 반복 안에 읽힐 만큼 오래 떠 있는지.
- JS(`rowSelector`·`rowSelected`·`dialogButton`·`toasts`)는 문법만 확인했고 실제 Chrome·UI5 에서 돌려 보지 못했다.
