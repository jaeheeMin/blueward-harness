# #316 양식 밖 열·소제목을 원본에서 막는다 (2026-10-14)

원칙: 산출물은 고객사 양식(템플릿)을 따른다. 양식 지도에 없는 열·칸은 원본(SRS md, Spec md)에 들어올 수 없다. 규칙이 스킬 문서에만 있으면 가드가 아니다 — 훅(저장)·PR·산출 셋 다 강제한다.

## 바뀐 것

- 새 규칙 종류 `form_columns`(`checker/rules/form_columns.py`). `원본: SRS` 는 SRS 요구사항 표 열과 상세 절 `####` 소제목을, `원본: 작업본` 은 Spec `## 양식 항목` 의 양식·시트·칸·표·서술·표 열을 양식 지도와 대조한다. 위반 메시지는 `양식 밖 열: X. 허용(…): …. 다음: 양식 지도에 있는 열 이름으로 고치거나 … 지도를 먼저 고친다`.
- 산출(`checker/export.py`)과 같은 목록을 쓴다: `srs_allowed`, `srs_offenders`, `spec_offenders`(이름 정규화도 `norm` 하나). 산출은 양식 밖 이름을 하나씩이 아니라 전부 모아 알리고 멈춘다(종료코드 2 그대로, `다음:` 안내 추가).
- 로더(`checker/loader.py`)가 규칙 params 에 `_rules_dir`(규칙 파일 폴더)를 넣는다. 훅은 검사할 문서만 임시 폴더로 옮겨 `--root` 를 그쪽으로 돌려서 문서 경로로는 기준 폴더의 지도를 못 찾기 때문이다.
- skeleton `rules/ssot.yaml`(`원본: SRS`, `기본_소제목: [설명, 완료 조건]`)·`rules/spec.yaml`(`원본: 작업본`)에 기본으로 켬. skeleton `SRS.md` 틀·`rules/README.md`·`checker/README.md`·srs·spec SKILL.md("검사가 막는다")·길잡이(SRS 만들기 탭 열 설명과 "양식 밖 열" 주의, Spec 만들기 탭, 레일 0.10.75) 갱신.
- 테스트: `checker/tests/test_form_columns.py`(SRS 지도 있음/없음, Spec, 훅 경로, 검사 불능), `test_export.py`(여러 개를 모두 알림), `test_registry.py`(종류 열 개).
- Plugin version 0.10.74 → 0.10.75.

## 설계 판단

- 새 규칙 종류로 했다. `md_table` 은 열이 고정된 절 하나를 보는 규칙이라 지도 파일을 읽어 열 목록이 정해지는 이 검사와 맞지 않는다. 열 목록은 코드가 아니라 양식 지도(데이터)에서 나온다.
- 기준 하나: 양식 지도. 지도가 없는 저장소는 SRS 틀(템플릿)의 요구사항 표 열 + 엔진 기본 `다음 단계`, 상세 소제목은 틀의 열 + 규칙 데이터 `기본_소제목`(틀 본문이 "양식이 없으면 설명, 완료 조건").
- 빠진 열은 허용(#243): 지도 열이 표에 없어도 위반이 아니다. 모르는 열만 거절한다.
- 지도를 못 읽음(깨진 yaml, 시트 없음), `원본: SRS` 지도가 둘 이상인데 고르지 않음, 틀에 요구사항 표가 없음 → ConfigError(종료코드 2, 검사 불능). 위반으로 뭉개지 않는다.
- 표·소절 구조가 깨져 열을 읽을 수 없는 문서는 위반으로 낸다(문서를 고쳐야 하고 산출도 같은 이유로 거부). 문서에 `## 요구사항` 절·표가 없는 건 이 규칙이 말하지 않는다(`required_sections` 소관).
- 산출 종료코드는 바꾸지 않았다. 양식 밖 이름은 원래 종료코드 2("읽지 못함")로 멈췄다(건너뛰지 않음). 바뀐 건 첫 하나가 아니라 전부 알리는 것과 `다음:` 안내다.

## 4번 점검 — 빈틈과 막은 것

| 대상 | 훅·PR | 산출 | 조치 |
|---|---|---|---|
| Backlog(SRS) 표 열 | 없었음 | 이미 멈춤 | `form_columns` 로 막음 |
| Backlog(SRS) 상세 소제목 | 없었음 | 이미 멈춤 | 막음 |
| 개발사양서(Spec `## 양식 항목`) 칸·소제목·표 열·시트 | 없었음 | 이미 멈춤 | `원본: 작업본` 으로 막음 |

| Spec 의 지도 없는 양식 | 없었음 | 지도 없음 오류 | 위반으로 막음 |

## 검토 반영

- 지도 모양(`칸[].항목`, `서술[].이름`, 표 `열` 사전, `md_전용` 목록)을 `_valid_map` 이 검증하고, 읽다 KeyError·TypeError 가 나도 검사 불능(종료코드 2)으로 올린다. traceback 으로 죽어 위반(1)과 같아지지 않는다.
- `지도_폴더` 를 명시했는데 폴더가 없으면 검사 불능. Spec 은 지도 폴더 자체가 없어도 검사 불능. 기본 폴더가 없을 때만 SRS 는 틀 기준으로 본다.
- `## 요구사항` 절·표 없음은 `export.SrsPartMissing` 예외로 구분한다(메시지 문자열 비교 제거).
- `export.norm` 에 NFC 정규화 추가(NFD 로 쓴 한글 이름 오탐 방지).

## 못 막은 것 (알려 둠)

- `### REQ-` 가 아닌 `###` 아래 `####` 는 파서가 조용히 무시한다(산출에도 안 나가는 자리). 열은 아니라서 막지 않았다.
- 지도(`templates/forms/*.yaml`)만 고친 PR 에서는 이미 있는 SRS 를 다시 검사하지 않는다(PR 검사는 바뀐 문서만 본다). 지도에서 열을 지우면 기존 SRS 가 다음에 바뀔 때 걸린다.
- 칸 값, 서술 본문, 표 행 개수 한도는 이 규칙이 아니라 산출이 본다(값의 내용은 양식 밖 이름 문제가 아니다).

## 배포 순서와 남은 일

1. 병합 → `release-tag` 가 엔진 `v0.10.75`, `stable` 을 붙인다. `git ls-remote --tags origin` 으로 `stable` 이동을 확인한다.
2. 팀원 플러그인 0.10.75 이상(훅은 `v{version}` 태그 엔진을 받는다). 그 뒤에 각 Project Repository(public-cloud 등)의 `rules/ssot.yaml`·`rules/spec.yaml` 에 `form_columns` 를 켠다. 먼저 켜면 `'form_columns' 는 모르는 규칙 종류다` 로 *모든 문서 유형*이 검사 불능이 된다(규칙 파일을 읽는 순간 터진다). skeleton 은 기본으로 켜 두었으니 새 scaffold 는 `stable` 이 0.10.75 이상일 때만 쓴다. 새 규칙은 이 저장소에서 기존 Project Repository 로 자동으로 오지 않는다(요청 필요).
3. public-cloud 의 기존 SRS 가 새 규칙에 걸리는지(열·소제목) 켜기 전에 한 번 돌려 본다. 걸리면 SRS 를 고치거나 지도를 먼저 고친다.
4. 병합 뒤 길잡이를 아티팩트에 다시 올린다(`docs/guide/README.md`).
