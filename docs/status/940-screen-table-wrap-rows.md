# #940 화면 그림 결과 테이블이 1칸으로도 넘치면 여러 줄로

## 배경

#939·#941 은 결과 테이블이 `칸_수.열` 너비로 넘치면 열 너비를 1칸으로 좁혔지만, 1칸으로도 영역 너비(C7:S14 = 17칸)를 넘치는 18열부터는
거부했다. public-cloud DEV-012(생산계획 보드)는 일자 열이 조회 일수만큼 늘어 17열을 넘을 수 있다.

## 바꾼 것

- `checker/screen_draw.py`: `layout(wrap=True)` 는 결과 테이블을 영역 너비만큼의 열씩 여러 줄 묶음으로 나눈다(묶음마다 머리글 + `빈_행` 줄,
  묶음 사이에 빈 줄 하나 — 필터 바 뒤 빈 줄과 같은 관례). `draw` 는 1칸으로도 넘칠 때만 이 배치를 시도하고, 행이 모자라면 그때 거부한다
  (사유는 나눈 배치 기준이라 "(행)"). 액션 묶음은 첫 묶음 오른쪽 끝 = 영역 오른쪽 끝(기존 계산 그대로). 경고는 #941 문구와 합쳐 한 줄
  "…(N개) 열 너비를 1칸으로 줄이고 M줄로 나눠 그렸다"(`칸_수.열` 이 이미 1 이면 "…(N개) M줄로 나눠 그렸다").
- 17열 이하(또는 1칸·2칸으로 들어가는 표)는 이 길을 타지 않아 이전과 셀 하나까지 같다(`wrap=False` 는 `per_band` 가 전체 열 수라 좌표식이 같다).
- 변경 표시(`screen_diff`)는 합친 목록을 그대로 `layout` 에 넘기므로 나눈 배치에서도 각 열 칸에 찍힌다.
- 스킬 문서(`form-map.md` 화면 그리기·멈춤, `spec/SKILL.md`), 길잡이, plugin.json 0.10.282, whats_new.json 갱신.

## 시험

- `test_screen_draw.py`: 18열 → 2줄(C~S, 둘째 줄 1열, 경고, 액션 위치), 34열 2줄, 35열 거부(행), 칸_수.열 1 에서 나눔,
  기존 8·9·17열 시험 그대로. 18열 거부 시험은 행이 모자란 입력으로 바꿈, `--check` 는 35열로.
- `test_screen_diff.py`: 19열(삭제 포함)이 나뉠 때 둘째 줄 열에 번호·색.
