## git 저장소가 아니거나 판정 못 한 세션 — 정한 규칙
감추지도 어느 저장소라고 지어내지도 않는다. **어느 프로젝트를 보든 보이고**, 줄에 점선 표를 붙인다.
- 폴더는 있는데 git 저장소가 아님(`no`): `git 저장소 아님`
- 폴더가 없음·git 을 실행하지 못함·작업 폴더 모름, 또는 위로 `.git` 이 있는데 git 이 못 읽음(Windows 의 dubious ownership·권한·망가진 worktree)(`unknown`): `저장소 확인 못 함`. 서버는 이 판정을 기억하지 않는다.
- 화면은 `no`·`unknown` 이 하나라도 있으면 60초 뒤 다시 묻는다(`git init`·잠깐 없던 폴더·git 시간 초과가 풀리면 따라온다).
- 아직 판정을 받지 못한 새 폴더: 표 없이 보인다(곧 받는다).
- 판정 자체를 못 읽었거나 마지막 폴더가 저장소가 아니면 거르지 않는다(모든 세션). 판정을 받기 전에는 Post 홈이 숫자를 그리지 않는다(거르기 전 숫자가 잠깐 보이지 않게).

## 독립 리뷰(sonnet, 읽기 전용) 반영
- Sauce 출력·동작이 바뀌는 경로 없음(flow-ui 는 `Array.from(kit.sessions.values())` 한 곳만 씀).
- 고침: ① 파이프라인이 고른 프로젝트와 상관없이 서버 마지막 폴더의 저장소 칸을 같이 보임 → 고른 프로젝트 폴더를 쓰고(`kit.home`), 저장소 판정 뒤에 읽음. ② 화면이 `no`·`unknown` 판정을 다시 묻지 않음 → 60초 뒤 다시 물음. ③ git 실패(종료코드 128)를 모두 `저장소 아님` 으로 단정 → 위로 `.git` 이 있으면 `unknown`.
- 고치지 않음(기록): 판정을 받기 전의 새 폴더 세션은 보이는 쪽으로 친다 — 그 사이(보통 1초 안) 다른 저장소 세션의 브라우저 알림이 한 번 뜰 수 있다. 알림을 보류하면 같은 저장소 세션의 알림을 잃을 수 있어 보이는 쪽을 골랐다. 팀 기록 칸(`/api/trouble`)·연결 끊긴 사이 터미널로 넘어간 요청 수(`checkHandoff`)는 세션 목록이 아닌 PC 전체 기록이라 거르지 않았다. 프로젝트를 바꾼 직후 파이프라인은 새 결과가 올 때까지 앞 프로젝트 칸이 잠깐 남는다(서버 캐시라 짧음). 첫 `/api/repos` 는 폴더마다 `git rev-parse` 를 한 번씩 해서 폴더가 많으면 수 초 걸릴 수 있다(시험 세계 9폴더 0.08초).
