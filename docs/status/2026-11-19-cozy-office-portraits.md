# Cozy Office 세션 사람 그림을 사무실 장면의 캐릭터로 (2026-11-19, 합류 2)

브랜치 `post/cozy-merge`(worktree `cozy-merge`), 합류 1(50dee9d) 위에 이어서 커밋했다.
이슈·PR·판 올리기·새 소식 없이 이 브랜치에 커밋만 했다(로컬 main 합류는 뒤 회차).

## 무엇을 했나
세션을 나타내는 사람 그림을 전부 오늘 화면 사무실 장면의 그 사람으로 바꿨다. 같은 번들의
`BHOfficeScene.portrait(sessionId, { state, crop, animate })` 를 쓴다 — 장면과 같은 코드가 같은 세션 id 로 그리니
생김새(피부 · 머리 · 옷)가 어긋날 수 없고, 몸짓은 상태를 따른다(답을 기다림 = 손 흔듦, 막힘 · 확인 못 함 = 머리에 손,
일하는 중 = 타자, 승인 기다림 = 서 있음, 끝 = 손 들고 활짝, 쉼 = 찻잔).

| 자리 | 전 | 지금 |
|---|---|---|
| 오늘 덱 카드 머리, 질문 · 승인 카드 머리(`.po-ask-h`) — 34×40 | 라인아트 `<img>` | `crop: 'bust'`, 움직임 |
| 세션 화면 머리(`post-session.js here()`) — 88×104(좁으면 64×76) | 라인아트 `<img>` | `crop: 'half'`, 움직임 |

| 오늘 화면 「내 세션」 두 단 목록 | 글자 칸 `.po-ava` | 위와 같은 `avatar(…, { size: 'sm' })` |

## 정한 것과 까닭

### 작은 칸(30×36)도 글자에서 얼굴로 바꿨다
Aside 로 찍어 확대해 보니 30×36 에서도 머리 모양 · 피부 · 옷 색 · 몸짓(손 흔듦, 머리에 손, 찻잔)이 읽힌다.
#1066 이 글자로 바꾼 까닭은 라인아트 그림을 작게 자르면 팔 · 소품이 겹쳐 보여서였는데, `bust` 는 처음부터 머리 · 어깨만
크게 그린 그림이라 그 문제가 없다. 그래서 「같은 세션 = 같은 사람」 을 목록에서도 지킨다.
- 칸 모양은 큰 칸과 같은 것(둥근 윗변 · 아래 턱 · 상태 바탕색)이다. 글자 아바타의 동그라미(32×32)는 그림 비율(0.85 : 1)과 안 맞는다.
- 목록은 100줄이 넘을 수 있어 작은 칸은 늘 멈춘 그림이다(`animate` 끔). 아래 「성능」.
- 글자 아바타가 주던 「제목 첫 글자」 는 없어졌다. 제목은 바로 옆 줄에 있고(접힌 레일은 `title` · `aria-label`), 그림은 전부터 `aria-hidden` 이다.

### 번들이 없을 때는 옛 그림을 그대로 쓴다(`static/post/people/` 는 지우지 않았다)
`window.BHOfficeScene` 이 없거나 `portrait` 가 없거나(옛 번들) 그리다 예외가 나면 `portraitOf` 가 `null` 을 주고,
부르는 쪽이 전과 같은 그림을 쓴다: 큰 칸은 라인아트 직원, 작은 칸은 글자 아바타, 요청 화면은 라인아트 직원이 손을 든다.
- `people/` 는 번들이 안 실렸을 때의 대체 장면 `Scene()` 도 쓴다(합류 1 이 남긴 길). 그림만 지우면 그 장면이 깨진다.
- 시험이 그 파일들을 본다(`people/mint/walk-1.svg` 를 받아 보는 시험, 그림 안 묶음을 대조하는 G1 시험).
- smoke 의 가짜 DOM 에는 번들이 없다. 번들이 없을 때의 길이 전과 글자 하나 다르지 않아 smoke 가 그대로 돈다.
- 옛 검토 담당 그림 파일(`post/clerk/*.svg`)도 대체 장면이 쓰므로 그대로 뒀다. 요청 화면에서는 더 안 쓴다.

### 요청 화면의 승인 · 계획도 그 세션 사람으로 바꿨다(문구 한 줄 포함)
처방 표에는 `clerk()` 의 질문 쪽 그림(`people/<who>/ask-*.svg`)만 적혀 있었다. 화면을 띄워 보니 승인 요청 화면에는
세션 사람이 아예 없고, 새 장면에 없는 인물인 옛 라인아트 「검토 담당」 만 있었다(그림체도 혼자 다르다). 끝의 기준이
「요청 화면에서도 같은 사람」 이라 승인 · 계획도 그 세션 사람이 손을 드는 그림으로 맞췄다 — 새 장면에서도 승인을 기다리는
세션은 자기 자리에서 손을 든다.
- 그림이 바뀌어 문구 「리뷰 룸에서 검토 담당이 네 승인을 기다려」 가 틀린 말이 됐다. 주어만 바꿨다(「세션이 손을 들고 네 승인을
  기다려. 누르면 승인 도장이 찍혀」). 바로 옆 질문 문구(「…손을 들고 네 답을 기다려」)와 같은 말투(반말)로 뒀다 — 해요체로
  바꾸는 것은 문구 회차가 두 줄을 같이 한다.
- 승인 뒤 도장과 도장 아랫줄의 「리뷰 룸」(`sealDesk`)은 안 건드렸다. 「검토 담당 · 리뷰 룸」 비유를 문구에서 어떻게 할지는 문구 회차 몫이다.
- 되돌리고 싶으면 `post-session.js clerk()` 와 `post-logic.js clerkLine` 두 군데다.

### 화면이 떠 있는 동안 설정이 바뀌면 그려진 그림을 갈아 끼운다
옛 그림은 CSS(`[data-fx="0"] .po-av-b { animation: none }`)가 멈췄다. 프로필 그림은 번들이 `requestAnimationFrame` 으로
움직여서, 설정 화면에서 효과 강도를 「차분」 으로 바꿔도 이미 그려진 그림은 다음에 다시 그려질 때까지 손을 흔들었다(실화면에서 찾음).
`bh-pref`(`fx`) 이벤트와 움직임 줄이기 변경을 듣고, 움직임이 지금 설정과 다른 그림만 새로 그려 바꾼다. 듣는 곳은 첫 그림을
그릴 때 한 번만 건다(번들이 없는 가짜 DOM 에서는 아무것도 안 건다).

### 번들에서 고친 것 (`ai-office-iso` `feat/diorama-office`, push 안 함)
오늘 화면은 가만히 둬도 15초마다 덱 카드와 「내 세션」 을 다시 그린다(45초 동안 덱 카드 7장 × 3번을 실화면에서 셌다).
프로필 그림은 그림마다 만든 순간을 0 으로 잡고 움직여서, 다시 그릴 때마다 손 흔드는 박자가 처음으로 튀었다(독립 리뷰가 짚음).
`src/diorama/portrait.ts` 가 움직이는 그림 전부에 한 시계(`CLOCK0`)를 쓰게 고쳤다 — 다시 그린 그림이 같은 박자로 이어진다
(따로 만든 두 그림의 몸짓이 한 프레임 뒤 같은 것을 실화면에서 확인). 멈춘 그림 · 자르는 자리 · 캐릭터 모양은 안 바뀌었다.
다시 빌드(`npx vite build -c vite.lib.config.ts`, 62KB)해 `static/post/office/office-post.js` 로 복사했다.

### 그 밖
- 칸 비율이 그림(0.85 : 1)과 조금 다른 곳(30×36, 56×64)이 있어 svg 에 `preserveAspectRatio="xMidYMax slice"` 를 준다. 빈 띠 없이 채우고 아래를 맞춘다.
- 바탕색은 전과 같다: 답을 기다림 = 파랑, 막힘 = 분홍, 끝 = 연두, 그 밖 = 베이지(`toneOf`). 요청 화면의 사람 칸도 다른 화면의 그 사람과 같은 파랑으로 맞췄다.
- 어둡게에서도 사람 칸은 밝은 바탕 그대로다(전부터). 프로필 그림은 낮의 제 색으로 그린다.

## 못 본 것
- Windows(Chrome · Edge)에서의 모습. 이 Mac 의 Aside(Chromium)로만 봤다.
- 실제 「움직임 줄이기」 운영체제 설정(브라우저 흉내 `emulateMedia` 로만 봤다), 화면이 떠 있는 동안 그 설정이 바뀌는 경우(코드와 가짜 DOM 시험으로만).

- 움직이는 그림의 눈에 보이는 매끄러움(손 흔들기 · 깜빡임)은 멈춘 화면 여러 장과 몸짓 값 대조로만 봤다. 영상으로 보지는 않았다.
- 터치, 47자리 넘는 세션의 장면(합류 1 과 같다).
