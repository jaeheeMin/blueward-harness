# #533 사용자 매뉴얼 화면 자동 캡처 도구 (2026-11-02)

## 바꾼 것

- `checker/manual_capture.py`: 캡처 엔진·CLI. 찍을 화면 목록(`*.capture.yaml`) 검증, 판정(`judge`), 그리기 위치(`plan_marks`), 작업본 갱신(`update_workbook`), 탭 고르기.
- `checker/cdp_client.py`: Chrome 디버깅 포트(CDP)에 붙는 최소 웹소켓 클라이언트(표준 라이브러리). `127.0.0.1` 만 허용한다(`localhost`·다른 PC·`/json/list` 가 돌려준 다른 호스트의 웹소켓 주소도 거부).
- `checker/manual_capture_js.py`: 페이지에 주입하는 스크립트(UI5 준비 확인, 요소 찾기, 열 스크롤, 입력 포커스, 덮개 그리기).
- `/harness:manual` SKILL.md 에 "캡처" 절(새 스킬을 만들지 않고 기존 스킬에 둠 — 같은 작업본을 읽고 쓰고, 목록·그림 이름 규칙이 한 곳에 있어야 해서). plugin.json 0.10.157(열린 #608 이 0.10.154 를 먼저 써 올림)(main 0.10.152, 열린 PR #595 가 0.10.153).
- README·CLAUDE.md 스킬 표 문구, `form-map.md` 매뉴얼 절에 캡처 연결, `checker/README.md`, 길잡이 매뉴얼 탭(안내·보안·못 하는 것).
- 시험 `checker/tests/test_manual_capture.py`.

## 찍을 화면 목록 형식

작업본 옆 `docs/manual/<LoB>/<번호>.<업무 제목>.capture.yaml`(Project Repository). 테넌트 주소는 `env/manual-capture.yaml` 의 `테넌트:`(주소만, 계정·비밀번호가 든 주소는 거부)와 `포트:`.

```yaml
화면:
  - 이름: 조회 조건            # 작업본 `### <양식> · 본문 · 조회 조건` 소절의 화면 이름과 같게
    앱: "#App-display"         # 선택. `#` 로 시작하는 Launchpad 해시(전체 주소는 거부)
    준비:                      # 선택. 입력(필터 값)·누르기(버튼)뿐
      - {입력: 플랜트, 값: "1010"}
      - {누르기: 이동}
    표시:                      # 번호는 목록 순서
      - {종류: 필터|버튼|열|그 밖, 이름: 화면에 보이는 글자, index: 2, 설명: 번호 설명 한 줄}   # index 선택
```

## 결정과 이유

- **그리기는 페이지 덮개(overlay)로**: 찍기 직전에 절대 위치 div(네모 테두리·번호 원)를 얹고 찍은 뒤 지운다. 이미지 라이브러리(Pillow)가 필요 없어 의존성을 더하지 않았다. 웹소켓도 표준 라이브러리로 직접 구현해 `pyproject.toml`·`uv.lock` 을 바꾸지 않았다.
- **배지 위치**: 네모 바깥 모서리(왼쪽 위 → 오른쪽 위 → 왼쪽 아래 → 오른쪽 아래) 중 그림 안에 다 들어가고 앞 배지와 안 겹치는 첫 자리. 어디도 안 되면 왼쪽 위를 그림 안쪽으로 민다.
- **판정**: 0개 `not_found`, 2개 이상 `ambiguous`(고르지 않음, 목록의 `index` 로 사람이 정함). 바깥 div 와 안쪽 button 처럼 거의 같은 영역(IoU 0.9 이상)은 하나로 센다.
- **못 찾은 요소가 있는 화면**: 찾은 것만 그려 `<화면>_미완_v<판>.png` 로 따로 저장하고 작업본은 고치지 않는다(번호 설명이 그리지 않은 번호를 가리키지 않게).
- **UI5 준비 대기**: 두 번 연속 준비 상태여야 한다(문서 로드 완료, `sap.ui.getCore()` 초기화, UI 더티 아님, busy 층 없음). 시간 초과는 검사 불능(종료 2). UI5 가 없는 페이지는 기본이 검사 불능이고 `--ui5 skip` 으로만 건너뛴다.
- **필터는 라벨+입력 칸 묶음**(`for` → 입력 칸의 UI5 컨트롤 루트, 없으면 라벨의 다음 형제). 입력 칸을 못 묶으면 라벨만 그리지 않고 not_found. **열**은 머리글부터 표 아래 끝(보이는 만큼), 가로 스크롤 밖이면 `scrollIntoView` 로 보이게 한 뒤 다시 잰다. 조상의 overflow 로 잘려 일부만 보이면 후보에서 뺀다.

## 로컬 Chrome 시험(로그인 없이, 2026-11-02)

로컬 HTML(필터 라벨·입력·버튼·가로 스크롤 표)을 전용 Chrome(`--remote-debugging-address=127.0.0.1 --remote-debugging-port=9222 --user-data-dir=<임시>`)으로 띄워 `--ui5 skip` 으로 끝까지 돌렸다(준비 단계 입력·누르기 포함).

- 필터(라벨 + 입력 칸 묶음)·버튼·그 밖·열 네모와 번호가 정확한 곳에 그려졌다. 가로 스크롤 밖 열(비고·담당자)은 스크롤해 찍었다. 맨 왼쪽 열과 맨 오른쪽 열을 한 화면에 요구하면 함께 보일 수 없어 not_found 로 보고했다(스크롤이 서로를 되돌림).
- 없는 버튼은 not_found, 같은 글자 둘은 ambiguous, `index` 로 고르면 found. 못 찾은 것이 있는 화면은 `_미완_` 그림 저장·작업본 미수정, 완료 화면은 작업본 `#### 그림`·`#### 번호 설명` 이 채워졌다.
- 끝낸 뒤 Chrome 을 닫고 프로필을 지웠다. **Windows 에서 프로필 경로가 길면(260자 초과) `Remove-Item` 이 실패했다** — 스킬은 짧은 경로(`$env:TEMP\manual-chrome`)와 `\\?\` 접두 삭제를 안내한다.
- 번호 배지가 그림 모서리에 닿는 요소(전체 폭 머리글)는 안쪽으로 밀렸다(`pushed`).

## 실제 테넌트 시험 절차(사람이 로그인해야 해서 하지 못했다)

1. Project Repository 에 `env/manual-capture.yaml`(`테넌트: https://<테넌트>/ui`)과 `docs/manual/<LoB>/<번호>.<업무 제목>.capture.yaml` 을 쓴다(작업본에 화면 소절이 있어야 한다).
2. `--check` 로 목록·소절·주소를 확인한다.
3. 전용 Chrome 을 띄운다(`SKILL.md` "캡처" 2). 그 창에서 사람이 로그인하고 앱 탭 하나만 남긴다.
4. 캡처를 돈다. UI5 준비 확인, 필터 라벨·입력 칸 묶음, 열 머리글, 팝업이 아닌 화면의 준비 단계가 실제 Fiori 에서 맞는지 본다.
5. 결과 PNG 를 눈으로 보고 `못 찾은 것` 을 확인한다. 끝나면 Chrome 을 닫고 프로필을 지운다.

## 확인하지 못한 것

- 실제 Fiori(UI5) 화면에서의 동작. 준비 판정의 `.sapUiBlockLayer`·`.sapUiLocalBusy`·`.sapMBusyDialog` 선택자, 스마트 필터 바의 라벨-입력 연결, `sap.ui.table` 의 열 머리글 구조는 #348 시험 기록과 UI5 구조에서 가정한 값이다(공식 문서로 대조하지 못했다).
- `Input.insertText`+Tab 으로 UI5 `Input` 값이 확정되는지(로컬 일반 input 에서만 확인).
- 팝업(값 도움말 대화상자 등)·여러 단계 준비·조건부 단계는 범위 밖이다. 같은 화면에 함께 보이지 않는 가로 스크롤 밖 열들은 한 그림에 못 담는다(화면을 나눠 찍는다).
- 창이 가려질 때의 렌더 멈춤은 `Page.bringToFront` 만으로 대응했고 가려진 상태에서 시험하지 않았다.
- 실제 Chrome 을 쓰는 자동 시험은 두지 않았다(Chrome 을 띄우는 시험은 메모리·환경 의존이 커서). `HARNESS_CHROME_TEST=1` 자리표시 시험만 있다.
- 완료 조건의 "DEV-008(생산실적 모니터링) 매뉴얼로 pptx 산출" 은 실제 테넌트 로그인이 필요해 하지 않았다.

## 독립 검토 뒤 보완

| # | 지적 | 고친 것 |
|---|---|---|
| 1 | 보이는 후보가 있어도 같은 이름이 화면 밖에 더 있으면 하나로 잡음 | 페이지 스크립트가 후보를 **화면 밖 포함 전부** 읽는 순서로 내고(`visible` 표시), `judge` 는 2개 이상이면 보이는 것이 하나뿐이어도 `ambiguous`. `index` 는 화면 밖을 포함한 전체 순서이고 고른 번째가 안 보이면 `not_found`. `scrollColumn` 이 `find` 와 같은 후보 목록·정렬·`index` 를 쓴다(정렬 키 `floor(y/10), x` 를 양쪽이 같게) |
| 2 | 같은 주소면 다시 안 열림, 출처 미확인 | 화면마다 강제로 다시 연다: 주소가 다르면 `Page.navigate`, 문서가 같으면(해시만 다르거나 같음) `Page.reload` 도 한다. 옛 문서에 `__mc_stale` 표지를 달아 새 문서로 바뀐 뒤에만 준비로 본다. 준비된 뒤 현재 주소의 출처가 테넌트 출처와 다르면 검사 불능 |
| 3 | 핸드셰이크·소켓 오류가 예외로 샘 | 핸드셰이크·쓰기·읽기의 `TimeoutError`·`ConnectionResetError`·`OSError`·`HTTPException` 을 `CdpError` 로 감싸고 실패하면 소켓을 닫는다. `ws://127.0.0.1@evil:80/` 처럼 계정 부분이 있는 주소와 잘못된 포트는 거부. env `포트:` 가 숫자가 아니면 검사 불능(종료 2) |
| 4 | 작업본 쓰기 | 화면마다 갱신 직전에 다시 읽고 임시 파일에 쓴 뒤 교체. `\n` 기준으로 나눠 줄마다 원래 줄바꿈 유지(새 줄은 우세한 줄바꿈), 코드펜스 안의 `#` 줄은 제목으로 보지 않는다 |
| 5 | 번호 설명 덮어쓰기 | 기존 `#### 번호 설명`(`미정` 제외)이 목록과 다르면 덮어쓰고 결과 JSON 의 화면 행에 `replaced_descriptions: {before, after}` |
| 6 | 테넌트 주소 | `https` 만, `?`·`#`·계정이 있으면 거부. 시험용 `http://127.0.0.1`·`file://` 은 `--allow-local-test` 로만 |
| 7 | 시험 | 가짜 CDP(`FakeTab`) 로 `run()` 전체(캡처 → 작업본 갱신 → 종료코드 0/1/2), 출처 확인·재열기·화면 밖 중복·`replaced_descriptions`·캡처 중 사람이 고친 작업본 보존, 갱신된 작업본을 `export` 가 읽어 pptx 로 산출(양식은 `test_export_pptx` 의 생성기 재사용), 가짜 서버로 핸드셰이크 RST·EOF·무응답 |

- 한계: `env` 의 `테넌트:` 에 쿼리를 못 쓰므로 `?sap-client=…` 가 필요한 테넌트는 쓰지 못한다(요청대로 거부). 필요해지면 허용 쿼리 키 목록을 따로 정한다.
- 한계: 해시 라우팅 대기는 "다시 로드한 새 문서 + UI5 준비 상태 두 번 연속" 이다. Fiori 가 렌더를 끝냈다는 전용 신호(예: 앱 라우터 완료 이벤트)는 쓰지 않았다(실제 Fiori 에서 확인하지 못해서).
- 한계: 같은 화면에서 맨 왼쪽 열과 맨 오른쪽 열처럼 함께 안 보이는 조합은 여전히 `not_found`(스크롤이 서로를 되돌림). 화면을 나눠 찍는다.
- 로컬 Chrome 시험을 한 번 더 돌렸다(`--allow-local-test`). 화면 밖 열과 라벨이 같은 이름이면 `ambiguous`(보이는 것/화면 밖 개수 표시), 고른 번째가 화면 밖이면 `not_found`, 두 번째 화면부터 앞 화면의 입력 값이 남지 않는 것(다시 열기)과 `replaced_descriptions` 를 확인했다. Chrome 은 닫고 프로필(짧은 경로 `%TEMP%\mc533`)은 지웠다.
