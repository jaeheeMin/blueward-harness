# #347 개발사양서 새 판에서 화면 변경 자동 표시 (2026-10-20)

개발이 끝난 뒤 화면 수정사항이 생겨 Spec 을 고쳐 새 판으로 산출하면, 어디가 바뀌었는지 산출물에 표시되지 않아 읽는 사람이 이전 판과 직접 비교해야 했다. 화면 구성이 Spec 의 표(#335 C2)로 남아 있으므로, 산출 때 지난 판과 비교해 바뀐 곳을 엔진이 직접 표시한다. 0.10.94.

## 정한 것 (사용자 승인)

- **비교 기준**: origin/main 의 같은 경로 Spec md(`git show origin/main:<root 기준 상대 경로>`). fetch 는 하지 않는다(`_in_origin_main` 과 같은 git 호출). 같은 양식 항목 절·시트·`#### <화면> 그림` 절을 찾아 지금 Spec 과 비교한다.
  - main 에 그 Spec 파일이 없음 → 첫 판, 표시 없이 그린다(경고 없음).
  - git 으로 origin/main 을 못 읽음 → 그릴 화면이 하나라도 있으면 `ExportError`(검사 불능, 종료코드 2) "지난 판과 비교하지 못했다 — git fetch 뒤 다시". 그릴 화면이 없으면 git 을 부르지 않는다.
  - main 판에 그 화면의 그림 절이 없음(시트 절 없음·해당 없음·캡처만 씀 포함) → 표시 없이 그리고 경고. 그림 절이 깨져 읽을 수 없음 → 검사 불능.
- **비교 단위**: 소절(필터 바·액션·결과 테이블)별 이름 짝짓기. 새 판에만 있음 = 추가, 옛 판에만 있음 = 삭제, 이름 변경 = 삭제 + 추가. 필터 바 `필수` 변경(빈칸은 N) = 수정(액션·결과 테이블엔 수정 없음). 설정 표 `조회` 자동 ↔ Go = `Go` 액션 추가/삭제(대상 "액션 · Go"). 순서만 바뀐 것은 표시하지 않는다.
- **중복 이름**: 같은 소절 안 중복(과 `조회: Go` 인데 `Go` 액션을 또 적은 것)은 `offenders` 의 "화면 항목 중복" 으로 거부(훅·PR·`--check`·산출이 같이 쓴다).
- **그리기**: 삭제 항목도 그림에 남긴다(옛 판에서 바로 앞에 있던 남은 항목 바로 뒤, 없으면 소절 맨 앞). 합친 목록으로 `layout` 을 돌려 영역을 넘치면 지금처럼 거절한다. 표시한 칸 글자 앞에 ①~⑳(21 부터 "(21)"), 번호는 필터 바 → Go → 액션 → 결과 테이블 순. 기존 상자 스타일 위에 덮어쓴다: 추가·수정 `{채우기: FFFF00}`, 삭제 `{채우기: D9D9D9, 글꼴_색: 808080, 취소선: true}`. 필터 바 추가/삭제는 라벨·입력, 수정은 라벨만. 액션은 그 칸. 결과 테이블 추가는 머리글만, 삭제는 머리글과 빈 행 모두.
- **스타일**: `cell_style` 에 `취소선`(bool) 추가. 지도 `화면:` 의 `스타일:` 이 `추가`·`수정`·`삭제` 이름도 받아 기본 표시 스타일을 통째로 바꾼다.
- **변경 내용 표**: 지도 `화면:` 의 새 선택 키 `변경: {시작_행, 최대_행, 열: {번호, 구분, 대상, 내용}}`. 머리글 줄은 양식에 있다고 보고 `시작_행` 부터 한 줄에 한 변경씩 쓴다. 지도 검증(키 모양·열 문자·양의 정수·지도가 맡은 칸/표/서술/유지·같은/다른 화면의 영역·캡처 범위·다른 변경 표와 겹침). 변경이 있는데 `변경:` 이 없음·최대_행 초과·쓸 칸에 값이 남음은 거부(자르지 않는다). 변경이 없으면 아무것도 안 쓴다.
- 캡처로 그리는 화면(`#### … 캡처`)은 비교하지 않는다.

- `checker/export.py`: `_origin_main_text`(origin/main 의 파일 내용, 첫 판/읽음/읽지 못함 구분), `build_form(spec_rel=)`(화면을 그릴 때 처음 한 번 지난 판 작업본을 읽음), `run` 이 작업본의 root 기준 상대 경로를 넘김.
- `checker/cell_style.py`: `취소선`.
- 문서: `form-map.md` 화면 절, spec `SKILL.md` 산출, 길잡이 "양식 파일 산출" 설명.
- 시험: `test_screen_diff.py`(새), `test_cell_style.py`(취소선), `conftest.py` 에 자동 fixture(시험용 임시 폴더는 git 저장소가 아니므로 지난 판 읽기를 "첫 판"으로 대신. `test_screen_diff.py` 만 이 fixture 를 끄고 진짜 git + 가짜 `refs/remotes/origin/main` 으로 시험).

## 판단한 것

- `--check` 도 같은 `build_form` 을 지나므로 지난 판 비교를 그대로 한다. 안 하면 `--check` 는 통과인데 산출은 검사 불능/거부로 갈리는 어긋남이 생긴다. 즉 `--check` 도 origin/main 이 있어야 한다.
- 지난 판의 그림 절은 느슨하게 읽는다: 표 밖 글·빈 이름·`미정` 행·모르는 설정은 무시하고, 같은 소절의 중복 이름은 처음 것만 쓴다. 엄격하게 읽으면 그 결함을 고치는 PR 이 영영 검사 불능으로 막힌다(검토 지적). 알려진 소절의 머리글이 틀렸거나 표를 읽을 수 없을 때만 검사 불능이고, 메시지로 main 의 그림 절을 먼저 고치라고 안내한다. 새 판 검사는 그대로 엄격하다.
- 지난 판 작업본에 `## 양식 항목` 절이 없으면 그림 절이 없는 것으로 보고(경고) 그린다.
- 설정 표 `조회: Go` 로 그리는 Go 는 표시 키를 따로 둔다(`("Go", "Go")`) — 같은 이름의 일반 액션과 섞이지 않게.

## 한계

- 병합 전 브랜치끼리 Spec 을 같이 고치면 각자 main 기준으로 비교한다(서로의 변경은 모른다).
- 지난 판은 "origin/main 의 같은 경로 Spec" 이다. Spec 파일 이름이 바뀌었으면(첫 판으로 보임) 비교하지 않는다.
- 엔진은 fetch 하지 않는다. 오래된 origin/main 이면 옛 판과 비교한다 — 산출 전 `/harness:sync` 나 `git fetch origin`.
