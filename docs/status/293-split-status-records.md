# #293 진행 기록을 작업별 파일로 나눠 충돌을 없앴다 (2026-10-13)

`docs/status.md` 의 "지금 어디까지 왔나" 절 끝에 PR 마다 기록 한 절을 붙이던
방식이 같은 자리 충돌을 만들었다. 최근 3일 main 커밋 24개 중 17개가 이 파일을
고쳤고, 하네스 세션 둘이 동시에 PR 을 내면 하나가 병합될 때마다 나머지가
충돌했다(#262, #276, #279, #290 등). 기록 한 절이 한 줄(최대 3,300자)이라
충돌 범위도 컸다. 사용자가 작업별 파일로 나누기로 정했다(2026-10-13).

바꾼 것. 새 기록은 작업마다 `docs/status/<이슈번호>-<영문-요약>.md` 한 파일이다.
머리에 `# #<번호> 제목 (날짜)` 한 줄을 두고 본문은 80자 안팎에서 줄을 나눈다.
지금까지의 기록 절 77개는 `docs/status/archive-until-2026-10-13.md` 한 파일로
내용 그대로 옮겼고, 이후 고치지 않는다. `docs/status.md` 에는 머리 안내,
현재 요약, 미결 사항, 설계 배경만 남겼다. 기록 목록(색인)은 두지 않는다.
색인이 다시 같은 자리 충돌을 만들기 때문이다. 찾을 때는 `docs/status/` 에서
이슈 번호로 파일을 찾거나 `grep -r` 로 찾는다.

안내도 고쳤다. `CLAUDE.md` 에 규칙 10으로 "진행 기록은 `docs/status/` 한 파일,
`status.md` 에 붙이지 않는다" 를 넣었고, 이 파일을 가리키던 `README.md`,
`plugins/harness/README.md`(#190 절 참조), `docs/sap-plugin-survey.md`,
`harness-handoff.md` 도 새 위치로 바꿨다. 테스트 안의 `docs/status.md` 경로
문자열은 "배포 대상이 아닌 파일" 표본이라 그대로 두었다.
