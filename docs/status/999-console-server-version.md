# #999 /harness:open 이 판이 다른 콘솔 서버를 그대로 다시 쓰는 문제 (2026-11-16)

## 배경
`ensure_server` 는 4873 에 우리 서버가 떠 있으면 판을 보지 않고 그대로 썼다. 플러그인을 갱신해도 예전에 띄운 서버가 계속 돌았다(11-03 에 띄운 0.10.164 서버가 최신 0.10.296 인데도 그대로). 화면 파일은 요청마다 디스크에서 읽어서 화면은 새 판, 서버는 옛 판인 섞인 상태가 됐다.

## 동작
| 떠 있는 서버 | 하는 일 |
|---|---|
| 서버 판이 플러그인 판과 같거나 더 새 판 | 그대로 쓴다(안내 없음) |
| 서버가 옛 판이고 pending 0 | `stop_server` 로 끄고 새로 띄운다. 안내: 옛 판이라 다시 띄웠다 |
| 서버가 옛 판이고 pending 있음 | 다시 띄우지 않는다. "옛 판이다(서버 판 → 플러그인 판)", 대기 요청 처리 뒤 `--stop` 후 다시 열라는 안내 |
| 서버가 옛 판인데 pending 을 못 읽음 | 끄지 않는다. 대기 수 확인 못 함 안내 |
| version 이 읽히지 않는 값 / 판이 없음 / 플러그인 판을 못 읽음 | 그대로 열고 확인 못 함 안내(같은 판으로 치지 않는다) |
| 끄기에 실패 | 옛 서버를 그대로 열고 못 끈 것을 알린다 |

## 판단: 다른 판이 아니라 옛 판일 때만 다시 띄운다
플러그인은 폴더마다 판이 다를 수 있다(`/harness:version` 의 "이 폴더 판"). 판이 "다르면" 다시 띄우면 옛 판 폴더에서 연 것이 새 서버를 옛 판으로 내리고, 두 폴더를 오가면 서버가 계속 재시작된다. 그래서 서버가 플러그인보다 작을 때만 다시 띄우고, 더 새 판이면 그대로 쓴다. 더 새 판은 문제가 아니라 안내도 두지 않는다(열 때마다 같은 줄이 나오지 않게). 판은 숫자로 비교한다(`1.2.10` > `1.2.3`).

## 판단: pending 이 없는 서버와 판이 없는 서버
실제 4873 에 떠 있던 0.10.164 는 health 가 `{"app": "harness-console", "version": "0.10.164"}` 로, 판은 있고 `pending` 이 없다. 판은 플러그인보다 작아 옛 판이지만 대기 요청 수를 알 길이 없다(다른 API 는 인증 쿠키가 필요하다). 모르는 채로 끄면 답을 기다리는 승인·질문이 사라질 수 있어 끄지 않고 "옛 판이야, 대기 수 확인 못 해 끄지 않았어, 처리 뒤 `--stop`" 만 안내한다. 이 서버는 한 번은 사용자가 `--stop` 으로 끄고 다시 열어야 하고, 그다음부터는 자동이다.
`version` 자체가 없는 응답은 어느 판인지 알 수 없어서 옛 판이라고 단정하지 않고 "판을 확인 못 함" 으로 둔다.

## 판 번호
