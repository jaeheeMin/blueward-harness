# #762·#763 세션 화면을 확정 시안(G-09·10·12·13)과 똑같이 맞추기

## 원인

- 승인 기다림(G-10)·갈래 끝남(G-12)이 git 상태(커밋 안 된 변경 · 열린 PR)로 "올릴 차례" 처럼 읽혀 내 차례(맨 위 띠 · 사이드바 · 머리말 · 홈 숫자)로 세어졌다.
- 세션 화면 치수가 시안과 달랐다: 제목 블록이 16px 아래(`.sess > * + *` 간격이 제목 줄에도 걸림), 눈썹·상태 줄 줄 높이, 접기 단추가 목록 머리 줄을 늘림, 오른쪽 칸 320(시안 300), 네 차례 카드가 대화 판 밖이라 글자 14(시안 14.5)와 간격 14(시안 12).

## 한 일

- 서버: `flows.phase_of` 로 `approval`(열린 PR + 대기 단계) / `finished`(갈래 끝남)를 가르고 세션 모델에 `phase` 를 싣는다. 둘은 `group` 을 `idle` 로 해 내 차례에서 뺀다(질문·승인 요청이 있으면 그쪽이 먼저). `gitstate` 는 PR 에 `stepChecks`(doc-guard·gitleaks status 결과)를 더한다.
- 화면 판정: 사이드바 "승인 기다림 · PR #n" / "끝 · PR #n 합쳐짐", 합쳐진 세션을 보는 동안 맨 위 띠 "PR #n이 합쳐졌어 — 다음은 <다음 갈래>", 머리말·부제(`지금 하는 일`·`끝남`), 승인 기다림에서는 할 일 카드·순서 알약·층 그림·산출물 칸·입력칸을 빼고 안내 한 줄과 [다른 작업 하러 가기]([다시 확인] 글자 단추 함께).
- 숫자 띠: 단계 · AI 진행(갈래 끝나면 뺌, 승인 기다림은 "끝") · 요구사항 · 개발 번호 · 작업 기록 · 검토 요청. 기억 칸을 뺐다(기억은 링·배너).
- G-09 "네 차례" 카드: 질문 한 줄 + 단추 둘(올리고 검토 요청 · 아직). 건너뛰기는 같은 줄 끝의 글자 단추로 남겼다. 못 보내는 세션이면 설명 줄이 그 이유로 바뀐다.
- G-10 검사 세 줄(문서 검사 / 비밀값 검사 / 팀 승인). G-12 다음 일 카드(넘길 내용 목록 · 단추 셋). G-13 시작 점검 두 줄(스스로 함, 잘못됐을 때만 다시 하기) · 질문을 대화 안에서 바로 고르기 · 질문이 있으면 "지금 할 일" 카드 숨김.
- 치수: 제목 블록 21px 줄 상자, 접기 단추 음수 마진, 오른쪽 칸 300~360, 갈래 칸을 대화 `.msgs` 안으로(12px 간격, 14.5px).

## 한계(데이터가 없어 시안대로 못 한 것)

- 요구사항·개발 번호 칸: 갈래가 끝나 다음 갈래가 계산된 뒤(G-12)에만 번호가 있다. G-09·G-10·G-13 에서는 칸을 만들지 않아 숫자 띠가 4~5칸이다(시안 6칸). 이슈 닫힘·새로 같은 꼬리말도 근거 데이터가 없어 붙이지 않았다.
- 눈썹 글자: 시안은 문서 이름("요구사항정의서")이고 콘솔은 갈래 이름("요구사항 만들기·바꾸기")이다.
- G-10 팀 승인 줄의 "승인자 1명 필요" 의 인원 수는 데이터에 없어 "승인자 확인이 필요" 까지만 쓴다.
- G-12 넘길 내용 목록: 인계 글은 눌러야 만들어지므로 목록은 스킬이 정해 둔 항목(번호 · 한 일과 남은 일 · 규칙과 세션 상태)만 보인다. "미결 사항 n개" 같은 값은 없다.
- 승인 기다림에서는 입력칸을 숨겼다(시안). 검사가 실패하면 남는다.
- 시험은 가짜 gh 라서 검사 이름(doc-guard·gitleaks)은 직접 넣은 값이다. 진짜 GitHub 의 status 이름은 확인하지 못했다(`pr-checks.yml` 의 "앞 검사 status 달기" 기준).
