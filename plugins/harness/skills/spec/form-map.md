# 양식 지도 형식

`/harness:spec` 이 읽는 양식 지도의 형식 정본이다. 양식 지도는 고객사 양식(xlsx
등)의 시트·칸·표·서술 위치를 적은 데이터 파일이고, Project Repository 의
`templates/forms/<양식 이름>.yaml` 에 둔다. 엔진은 `rules/` 만 읽으므로 이
파일은 doc-guard 검사 대상이 아니다. 스킬(사람·Claude)이 읽는다. UTF-8.

## 지도 파일

```yaml
양식: 개발사양서                      # 표시 이름. 파일 이름과 같게
설명: 화면·로직 개발 건의 기능 사양서   # 언제 쓰는 양식인지 한 줄 (스킬이 고르기 목록에 보여 줌)
템플릿: ../BW_개발사양서(Functional Spec)_CO-001_예산관리 센터 사용자 필드 추가_v1.0(템플릿).xlsx   # 이 지도 파일 기준 상대 경로
검사_규칙: ../../rules/dev-spec.yaml   # 완성본을 검사하는 doc-guard 규칙(없으면 생략)
산출:                                  # #192 가 쓴다
  폴더: docs/개발사양서
  파일명: "BW_개발사양서_{개발 ID}_{Title}_v{버전}.xlsx"   # {이름} 의 출처는 아래 `자리`. 검사_규칙의 filename 패턴과 맞아야 한다
  자리:                                # 선택. 생략한 {이름} 은 같은 이름의 `칸`
    버전: {표: Change History, 열: 주요내용, 행: 마지막}
    Title: {칸: Title, 떼기: "Title : "}
시트:
  - 이름: Cover                       # 템플릿의 실제 시트 이름 그대로
    설명: 개발 건 기본 정보            # 선택
    칸:                                # 라벨-값 칸
      - 항목: 개발 ID                  # md 작업본에 쓰는 이름
        위치: C3                       # 값을 쓰는 셀(병합이면 왼쪽 위 셀)
        필수: true
        설명: "모듈-번호-순번, 예: CO-006-01"   # 선택. 무엇을 적는지
        예시: CO-006-01                # 선택. 템플릿에 박혀 있는 샘플 값 — 실제 값으로 옮기지 않는다
      - 항목: Title
        위치: C4
        형식: "Title : {값}"           # 선택. md 에는 값만 적고, xlsx 에 쓸 때 형식을 적용한다
    표:                                # 머리글 + 여러 행
      - 이름: Change History
        머리글_행: 8
        시작_행: 9                     # 첫 데이터 행
        열:                            # 정규화한 머리글 이름: 열 문자
          요청일: B
          주요내용: C
          완료일: G
          수정자: I
          "No": K                      # No·Yes·On·Off 는 따옴표로 감싼다
        필수: false
        최대_행: 10                    # 선택. 데이터 행 수 한도
        짝: 승인 이력                  # 선택. 같은 시트 행에 나란히 놓이는 다른 표 이름
        여러_줄: 셀                    # 선택. 행|셀, 기본 셀
    서술:                              # 자유 서술 영역(번호 목록·설명문)
      - 이름: 기능설명
        위치: D3                       # 서술 셀 하나, 또는 줄마다 한 행인 범위(예 D3:D40)
        필수: true
        설명: 이벤트별 처리 로직을 번호 목록으로
```

필수 키는 `양식`, `템플릿`, `시트`(각 시트의 `이름`) 다.

## 규칙

- `시트` 는 템플릿의 모든 시트를 순서대로 적는다. 시트마다 `칸`·`표`·`서술`
  중 있는 것만 둔다. 이미지·도형뿐인 시트는 `설명` 에 그렇다고 적고 칸이
  없을 수 있다.
- 시트·칸·표·서술 모두 선택 키 `설명` 을 둘 수 있다. 무엇을 적는지, 쓰는
  방법(예: 짝 표의 행 맞춤)을 사람이 읽을 말로 적는다.
- `필수` 생략은 false. 시트 자체의 `필수` 는 두지 않는다 — 작업본에는 모든
  시트를 담는다. 해당 없는 시트·항목은 작업본에 `해당 없음` 으로 적는다.
- `예시` 는 템플릿 셀에 이미 들어 있는 샘플 값이다. 작업본에 옮기지 않는다.
  템플릿의 `XXXXXX` 같은 자리표시자도 `예시` 로 적는다.
- 수식 셀(예: 파일명을 읽는 `CELL("filename")`)은 `항목` 으로 두되 `자동: true`
  를 붙여 사람이 채우지 않음을 표시한다. 작업본에는 `자동` 이라고 적는다.
- 열 이름·머리글은 정규화해서 쓴다. 앞뒤 공백을 지우고, 줄바꿈과 연속 공백은
  공백 하나로 바꾼다. 지도의 `열` 키와 md 표 머리글은 정규화한 이름을 쓰고,
  xlsx 머리글과 대조할 때도 같은 정규화로 비교한다.
- `No`·`Yes`·`On`·`Off` 같은 열·항목 이름은 따옴표로 감싼다. 안 그러면 YAML 1.1
  이 불리언으로 읽는다.

### 산출.자리

파일명의 `{이름}` 이 어디서 오는지 적는다. 생략하면 같은 이름의 `칸` 값을 쓴다.

- `{칸: <항목 이름>}` — 그 칸의 값.
- `{표: <표 이름>, 열: <열 이름>, 행: 마지막|처음}` — 표의 그 열, 마지막 또는 처음 데이터 행의 값.
- 선택 `떼기: "<문자열>"` — 값 앞에서 그 문자열을 뗀다(예: `V1.0` 에서 `V`).

### 표 선택 키

- `최대_행` — 데이터 행 수 한도. 작업본을 쓰다 넘으면 사용자에게 알린다. 넘친 채로는 #192 가 산출을 거부한다.
- `짝` — 같은 시트 행에 나란히 놓이는 다른 표 이름. md 에서도 두 표의 행 수와 순서를 맞추고, 없는 값은 빈 칸으로 둔다.
- `여러_줄: 행|셀` — 기본은 `셀`(셀 안 줄바꿈). `행` 이면 md 셀의 `<br>` 로 나눈 줄을 시트의 다음 행들에 이어 쓰고, 다른 열은 첫 행에만 쓴다(예: Public Logic 의 기능설명).

### 칸 선택 키

- `형식` — 예 `형식: "테이블 ID : {값}"`. md 작업본에는 값만 적고, xlsx 에 쓸 때 형식을 적용한다.

## md 작업본 표기

기존 여섯 절(근거 요구사항, 개요, 상세 설계, 완료 조건, 참조, 변경 이력)은
그대로 두고 `## 양식 항목` 절을 `## 상세 설계` 뒤에 더한다. 양식을 여러 개
고르면 양식마다 반복한다.

```markdown
## 양식 항목

### 개발사양서 · Cover

양식 지도: [templates/forms/개발사양서.yaml](../../templates/forms/개발사양서.yaml)

| 항목 | 값 |
|---|---|
| 개발 ID | CO-006-01 |
| Title | 미정 |

#### Change History

| 요청일 | 주요내용 | 완료일 | 수정자 |
|---|---|---|---|
| 2026-10-06 | 최초 작성 |  |  |

#### 기능설명

1. ...

### 개발사양서 · Initial Screen

해당 없음
```

- `### <양식> · <시트 이름>` 소절, 칸은 `| 항목 | 값 |` 표, 표는
  `#### <표 이름>` + 머리글 그대로의 표, 서술은 `#### <서술 이름>` + 본문.
- 표 셀 안 줄바꿈은 `<br>` 로 쓴다.
- 서술 `위치` 가 범위면 한 줄에 항목 하나씩 쓴다(산출 때 줄마다 한 행이 된다).
- `해당 없음` 은 시트 단위로만 쓴다(소절 본문에 한 줄). 칸·표 안에서는 쓰지 않고
  빈 칸으로 둔다.
- 값을 정할 수 없으면 추측하지 않고 사용자에게 묻고, 그래도 없으면 `미정`.
  필수 항목이 `미정` 이면 마무리 안내에 목록으로 알린다.
- 지도 파일을 못 읽거나 형식이 틀리면 통과로 넘기지 않고 읽지 못했다고
  알린다. 양식 없이 쓰지 않는다 — 사용자가 양식 없이 쓰라고 할 때만 그렇게 한다.

## 산출(#192)과의 경계

이 문서와 `/harness:spec` 의 작업 단계는 md 작업본까지만 다룬다. xlsx 는
`python -m checker.export`(스킬 "양식 파일 산출")가 만든다. 동작은 다음과 같다.

- 칸은 `위치` 에 쓰고 `형식` 이 있으면 `{값}` 을 바꿔 쓴다. `자동` 칸은 쓰지 않는다.
  `미정` 은 빈 칸이다. 지도의 `예시` 가 있는 칸은 값이 없으면 샘플을 비운다.
- 표는 `시작_행` 부터 쓴다. 채우지 않은 템플릿 샘플 행(`최대_행` 이 있으면 그 범위)의
  열은 비운다. `최대_행` 이 없는 표가 템플릿 데이터 행보다 길어지면 마지막 데이터 행의
  서식을 복제해 행을 더한다. 표 아래에 지도의 다른 항목이 있으면 거부한다.
- 서술은 `위치` 가 한 셀이면 줄바꿈 포함 한 셀로 쓴다. 범위(예 `F38:I41`)면 템플릿이 줄마다
  한 행인 구조이므로 본문의 줄(빈 줄 제외, `<br>` 도 줄 나눔)을 범위의 첫 열에 행마다 하나씩
  쓰고 범위 안 나머지 샘플은 비운다. 줄 수가 범위 행 수를 넘으면 거부한다.
- 날짜(`YYYY-MM-DD`)는 칸 서식이 날짜 서식일 때만 날짜 값으로 쓰고, 정수는 숫자,
  나머지는 문자열로 쓴다.
- 거부(종료코드 1, 파일을 쓰지 않음): 필수 칸·표·서술이 `미정`/빈 칸, `최대_행` 초과,
  `짝` 표 행 수 불일치, 파일명 자리 값 없음, 파일 이름 금지 문자(`\ / : * ? " < > |`),
  같은 이름 파일이 이미 있음(이전 판은 덮지 않는다), 결과 파일명이 `검사_규칙` 의
  filename 패턴(`패턴`·`pattern` 둘 다 읽는다)과 다름, 셀 값이 32767자 초과, 표 행의
  셀 수가 머리글과 다름.
- 읽지 못함(종료코드 2): 작업본·지도·템플릿을 못 읽음, 작업본의 양식·시트·칸·표·열이
  지도에 없음, 시트를 템플릿에서 못 찾음, `자동` 표시 없는 수식 칸에 쓰려 함,
  작업본 형식 오류(표가 끊긴 뒤 다시 나옴, 머리글 다음 줄이 구분선이 아님, 같은 소절이
  두 번, 칸 표 머리글이 `항목 | 값` 이 아님), 양식 이름에 경로 구분자가 있음, 템플릿·
  `검사_규칙`·`산출.폴더` 가 Project Repository 밖을 가리킴(절대경로·`..` 모두), 그 밖의
  예상하지 못한 오류. 검사 불능이며 통과도 위반도 아니다.
- 쓰기는 원자적이다. 모든 산출물을 같은 폴더의 임시 파일로 먼저 쓰고 전부 성공해야 최종
  이름으로 바꾼다. 하나라도 실패하면 이번 실행이 만든 파일을 모두 지운다.
- 수식이 있는 통합문서는 열 때 다시 계산하도록 표시한다(파일명을 읽는 수식 등).
  xlsx 자체의 검사는 훅이 아니라 PR 의 Actions(doc-guard)가 한다.
- 경고(`warnings`): XML 에 넣을 수 없는 제어 문자는 지우고 항목별로 알린다. 해당 없음이거나
  작업본에 없는 시트에 그림·도형이나 지도 밖 셀 값이 남아 있으면 "템플릿 샘플이 남아
  있다" 고 알린다.

### 한계: 지도 밖 템플릿 샘플

지도에 없는 그림·도형·셀 값은 산출물에 그대로 남는다. 도형 삭제는 서식을 깨뜨릴 위험이
커서 지우지 않는다. 지도가 가리킨 칸·표 데이터 영역·서술 범위의 샘플만 비운다. 특히
화면 목업 시트(예: Display Screen)는 해당 없음으로 둬도 목업이 남으므로 `warnings` 가
나오면 엑셀에서 열어 직접 지운다.
