# 양식 지도 형식

`/harness:spec` 과 `/harness:srs` 가 읽는 양식 지도의 형식 정본이다. 양식 지도는 고객사 양식(xlsx
등)의 시트·칸·표·서술 위치를 적은 데이터 파일이고, Project Repository 의
`templates/forms/<양식 이름>.yaml` 에 둔다. 엔진은 `rules/` 만 읽으므로 이
파일은 doc-guard 검사 대상이 아니다. 스킬(사람·Claude)이 읽는다. UTF-8.

## 지도 파일

```yaml
양식: 개발사양서                      # 표시 이름. 파일 이름과 같게
설명: 화면·로직 개발 건의 기능 사양서   # 언제 쓰는 양식인지 한 줄 (스킬이 고르기 목록에 보여 줌)
템플릿: ../BW_개발사양서(Functional Spec)_CO-001_예산관리 센터 사용자 필드 추가_v1.0(템플릿).xlsx   # 이 지도 파일 기준 상대 경로
검사_규칙: ../../rules/dev-spec.yaml   # 완성본을 검사하는 doc-guard 규칙(없으면 생략)
산출:                                  # #192 가 쓴다
  폴더: docs/개발사양서
  파일명: "BW_개발사양서_{개발 ID}_{Title}_v{버전}.xlsx"   # {이름} 의 출처는 아래 `자리`. 검사_규칙의 filename 패턴과 맞아야 한다
  자리:                                # 선택. 생략한 {이름} 은 같은 이름의 `칸`
    버전: {표: Change History, 열: 주요내용, 행: 마지막}
    Title: {칸: Title, 떼기: "Title : "}
시트:
  - 이름: Cover                       # 템플릿의 실제 시트 이름 그대로
    설명: 개발 건 기본 정보            # 선택
    칸:                                # 라벨-값 칸
      - 항목: 개발 ID                  # md 작업본에 쓰는 이름
        위치: C3                       # 값을 쓰는 셀(병합이면 왼쪽 위 셀)
        필수: true
        설명: "모듈-번호-순번, 예: CO-006-01"   # 선택. 무엇을 적는지
        예시: CO-006-01                # 선택. 템플릿에 박혀 있는 샘플 값 — 실제 값으로 옮기지 않는다
      - 항목: Title
        위치: C4
        형식: "Title : {값}"           # 선택. md 에는 값만 적고, xlsx 에 쓸 때 형식을 적용한다
    표:                                # 머리글 + 여러 행
      - 이름: Change History
        머리글_행: 8
        시작_행: 9                     # 첫 데이터 행
        열:                            # 정규화한 머리글 이름: 열 문자
          요청일: B
          주요내용: C
          완료일: G
          수정자: I
          "No": K                      # No·Yes·On·Off 는 따옴표로 감싼다
        필수: false
        최대_행: 10                    # 선택. 데이터 행 수 한도
        짝: 승인 이력                  # 선택. 같은 시트 행에 나란히 놓이는 다른 표 이름
        여러_줄: 셀                    # 선택. 행|셀, 기본 셀
    서술:                              # 자유 서술 영역(번호 목록·설명문)
      - 이름: 기능설명
        위치: D3                       # 서술 셀 하나, 또는 줄마다 한 행인 범위(예 D3:D40)
        필수: true
        설명: 이벤트별 처리 로직을 번호 목록으로
```

필수 키는 `양식`, `템플릿`, `시트`(각 시트의 `이름`) 다.

## 규칙

- `시트` 는 템플릿의 모든 시트를 순서대로 적는다. 시트마다 `칸`·`표`·`서술`
  중 있는 것만 둔다. 이미지·도형뿐인 시트는 `설명` 에 그렇다고 적고 칸이
  없을 수 있다.
- 시트·칸·표·서술 모두 선택 키 `설명` 을 둘 수 있다. 무엇을 적는지, 쓰는
  방법(예: 짝 표의 행 맞춤)을 사람이 읽을 말로 적는다.
- `필수` 생략은 false. 시트 자체의 `필수` 는 두지 않는다 — 작업본에는 모든
  시트를 담는다. 해당 없는 시트·항목은 작업본에 `해당 없음` 으로 적는다.
- `예시` 는 템플릿 셀에 이미 들어 있는 샘플 값이다. 작업본에 옮기지 않는다.
  템플릿의 `XXXXXX` 같은 자리표시자도 `예시` 로 적는다.
- 수식 셀(예: 파일명을 읽는 `CELL("filename")`)은 `항목` 으로 두되 `자동: true`
  를 붙여 사람이 채우지 않음을 표시한다. 작업본에는 `자동` 이라고 적는다.
- 열 이름·머리글은 정규화해서 쓴다. 앞뒤 공백을 지우고, 줄바꿈과 연속 공백은
  공백 하나로 바꾼다. 지도의 `열` 키와 md 표 머리글은 정규화한 이름을 쓰고,
  xlsx 머리글과 대조할 때도 같은 정규화로 비교한다.
- `No`·`Yes`·`On`·`Off` 같은 열·항목 이름은 따옴표로 감싼다. 안 그러면 YAML 1.1
  이 불리언으로 읽는다.

### 산출.자리

파일명의 `{이름}` 이 어디서 오는지 적는다. 생략하면 같은 이름의 `칸` 값을 쓴다.

- `{칸: <항목 이름>}` — 그 칸의 값.
- `{표: <표 이름>, 열: <열 이름>, 행: 마지막|처음}` — 표의 그 열, 마지막 또는 처음 데이터 행의 값.
- `{메타: <이름>}` — SRS.md 문서 머리(첫 `##` 앞)의 `이름: 값` 줄(예: `버전: 0.2`). 원본이 SRS 인 지도용이다.
  `메타: 버전` 은 앞의 `v` 를 뗀다.
- 선택 `떼기: "<문자열>"` — 값 앞에서 그 문자열을 뗀다(예: `V1.0` 에서 `V`).

### 표 선택 키

- `최대_행` — 데이터 행 수 한도. 작업본을 쓰다 넘으면 사용자에게 알린다. 넘친 채로는 #192 가 산출을 거부한다.
- `짝` — 같은 시트 행에 나란히 놓이는 다른 표 이름. md 에서도 두 표의 행 수와 순서를 맞추고, 없는 값은 빈 칸으로 둔다.
- `여러_줄: 행|셀` — 기본은 `셀`(셀 안 줄바꿈). `행` 이면 md 셀의 `<br>` 로 나눈 줄을 시트의 다음 행들에 이어 쓰고, 다른 열은 첫 행에만 쓴다(예: Public Logic 의 기능설명).

### 칸 선택 키

- `형식` — 예 `형식: "테이블 ID : {값}"`. md 작업본에는 값만 적고, xlsx 에 쓸 때 형식을 적용한다.

### 시트·서술의 선택 키 (견본 지우기와 두 칸 서술, #335)

고객사가 준 견본 xlsx 에는 지도 밖 샘플(셀 값, 그림·도형, 다른 파일을 가리키는 외부 참조)이 섞여 있다. 아래 키로
"무엇을 지울지" 를 지도에 데이터로 적고, `python -m checker.blank_template` 가 그대로 지운 빈 양식을 만든다.

```yaml
외부_참조_지우기: true          # 최상위. 선택
시트:
  - 이름: Display Screen
    그림_지우기: true           # 이 시트의 그림·도형(drawing)을 뗀다
    비우기: [B3:C10, F5]        # 지도 밖 칸의 값만 지운다(서식·병합 유지)
    유효성_지우기: [F13:J16]    # 이 범위와 겹치는 드롭다운(데이터 유효성)을 뺀다
    서식_지우기: [C10:G14]      # 값과 함께 셀 서식(테두리·채우기)을 열 기본 서식으로 되돌리고 병합을 푼다
    서술:
      - 이름: 화면 설명
        위치: D17:E33
        열: {제목: D, 설명: E}  # 한 행에 제목 칸과 설명 칸이 따로 있는 구조
```

- **기본 동작(키 없음)** — 빈 양식은 지도가 "채울 자리" 로 정한 곳의 견본 값을 지운다: 칸 `위치`(`자동: true` 칸은 산출이
  건드리지 않으니 제외), 표 데이터 영역(`시작_행` 부터, 머리글 행 제외; `최대_행` 이 없으면 값이 이어지는 마지막 행까지, 열마다),
  서술 `위치` 범위(두 칸 `열` 이어도 범위 전체). 라벨·머리글·작성 안내문은 지도가 맡지 않은 칸이라 그대로 남는다. 산출이 값 없이
  두면 비우는 곳과 같은 함수(`export.fill_ranges`)를 쓰므로 **빈 양식 = 산출이 아무 값도 안 넣었을 때의 모습** 이다. 수식 셀은
  지우지 않고 알림으로 알린다.
- `비우기: [범위…]` — 지도 밖 시트 범위(`A1` 또는 `B2:D9`)의 값을 지운다. 지도의 `칸`·`표`(시작_행부터 `최대_행`, 없으면 끝까지)·
  `서술` 위치·`유지` 와 겹치면 지도 오류다(종료코드 2). 수식 셀은 지우지 않고 알림으로 알린다. 지운 문자열은 공유 문자열
  (sharedStrings)에서도, 그 문자열을 가리키는 다른 칸이 없을 때만 본문을 비운다(번호는 유지). 산출(`checker.export`)도 같은
  범위를 지운다(템플릿이 이미 비어 있어도 안전망).
- `그림_지우기: true` — 그 시트의 `<drawing>` 과 시트 관계를 떼고, 다른 시트가 안 쓰는 drawing 파트와 그 안의 이미지(media)를
  지우고 `[Content_Types].xml` 의 해당 항목을 정리한다. 인쇄 설정(printerSettings) 등 다른 관계는 둔다. drawing 이 차트·도식·
  삽입 개체를 가리키거나 시트에 메모(legacyDrawing)·OLE·컨트롤이 있으면 지원하지 않는다(종료코드 2).
- `유효성_지우기: [범위…]` — 그 범위와 겹치는 데이터 유효성(드롭다운; 표준·x14 확장 모두)을 뺀다. 화면 목업 영역의 직접 입력 목록
  처럼 견본 화면의 일부인 드롭다운에 쓴다. 한 항목의 `sqref` 가 일부만 겹치면 겹친 부분만 빼고 나머지(수식·종류)는 그대로 둔다.
  항목이 다 빠진 묶음과 그것만 담던 x14 `ext` 도 걷는다. 이 처리는 외부 참조 지우기보다 먼저라서, 외부 이름을 쓰던 드롭다운을
  이 키로 빼면 `외부_참조_지우기` 와 충돌하지 않는다. `A:A` 같은 열 전체 `sqref` 는 해석하지 않고 그대로 두며 `notices` 로 알린다.
  범위가 아무 유효성도 못 지웠으면(겹치는 항목이 없으면) 조용히 넘기지 않고 `notices` 에 `validation-unmatched`(시트·범위)로 알린다. 결과 보고의 `validations_cleared` 에 시트별 `removed`(통째로 뺀 항목)·`trimmed`(일부만 뺀 항목)가 나온다.
- `서식_지우기: [범위…]` — 견본 목업 표처럼 값을 지워도 테두리·채우기·병합이 빈 표 모양으로 남는 곳에 쓴다. 범위 셀의 값을 지우고
  셀 서식(`s`)을 그 열의 기본 서식(`<col>` 의 style, 없으면 0)으로 되돌리며, 범위 안에 통째로 든 병합(mergeCells)을 푼다. 값 지우기를
  포함하므로 `비우기` 와 같이 써도 된다. `styles.xml` 은 건드리지 않는다(서식 목록은 그대로, 셀이 가리키는 번호만 바뀜). 범위 안에 수식 셀이
  있거나 병합이 범위와 일부만 겹치면 종료코드 2 다. 조건부 서식은 sqref 가 범위 안에 통째로 들면 빼고, 일부만 겹치면 상대 참조가
  틀어질 수 있어 고치지 않고 `notices`(`conditional-format-overlap`)로 알린다(x14 조건부 서식은 겹치면 알리기만 한다). 지도의
  칸·표·서술·`유지` 범위와 겹치면 지도 오류다. 행 단위 서식(`<row>` 의 s)은 건드리지 않는다. 결과 보고의 `formats_reset` 에 시트별
  `cells`(서식을 바꾼 셀 수)·`merges_removed`·`conditional_formatting_removed` 가 나온다.
- `유지: [범위…]` — 지우지 않을 범위. 이번 판은 키만 인정한다(남은 견본 검사는 이어서 붙는다).
- `외부_참조_지우기: true` — 최상위 키. externalLinks 파트와 그 관계, `workbook.xml` 의 `externalReferences`, `[N]` 외부 참조를
  쓰는 이름 정의를 지운다. 그 이름을 쓰는 데이터 유효성(드롭다운, 표준·x14)·셀 수식·조건부 서식·차트가 하나라도 있으면 지우지
  않고 어디서 쓰는지 알리며 종료코드 2 로 멈춘다(값을 템플릿 안에 넣을지는 사람이 정한다). `#REF!` 를 가리키는 이름은 외부
  참조가 아니라 그대로 두고 알린다.
- 서술 `열: {제목: 열 문자, 설명: 열 문자}` — 위치가 `D17:E33` 처럼 두 칸 구조일 때 쓴다. md 본문의 줄마다 `제목 | 설명` 으로
  쓰면 제목은 `제목` 열에, 설명은 `설명` 열에 한 행씩 간다(설명 안 줄바꿈은 `<br>`, `|` 가 없는 줄은 제목만). 두 열은 `위치`
  의 열 범위 안이어야 한다. `열` 이 없는 서술은 위의 한 칸 동작 그대로다.

### 셀 스타일 정의 (#335 C1)

화면 시트에 표·버튼 모양을 그릴 때 쓰는 스타일 정의의 형식이다(`checker/cell_style.py`). 지도 시트 항목의 `화면:` 의 `스타일` 이 읽는다(아래).

```yaml
채우기: DDEBF7         # RRGGBB, 또는 없음
테두리: 얇게           # 얇게 | 중간 | 굵게 | 없음 (범위의 모든 칸 네 변)
테두리_색: "000000"    # 테두리가 선 종류일 때만
굵게: true
글꼴_크기: 9
글꼴_색: "000000"
가로: 가운데           # 왼쪽 | 가운데 | 오른쪽
세로: 가운데           # 위 | 가운데 | 아래
줄바꿈: true
```

적은 키만 덮어쓰고 나머지는 셀이 원래 가진 서식(글꼴 이름·숫자 형식 등)을 따른다. 모르는 키·잘못된 값은 무시하지 않고 오류로 멈춘다.

### 화면 그리기: 시트 `화면:` 과 작업본 `#### <화면> 그림` (#335 C2)

개발사양서의 화면 시트(Initial Screen, Display Screen)에 Spec 의 화면 구성(조회 조건·버튼·결과 표)을 셀·테두리·채우기·병합으로 그린다.
영역·칸 수·색은 코드가 아니라 지도(데이터)가 정한다.

```yaml
시트:
  - 이름: Display Screen
    비우기: [C7:S14]            # 견본을 먼저 지운다(산출은 지운 뒤에 그린다)
    화면:
      - 이름: 화면 1              # 작업본의 `#### 화면 1 그림` 과 맞춘다
        영역: C7:S14              # 이 안에만 그린다
        칸_수: {라벨: 2, 입력: 3, 버튼: 2, 열: 2, 간격: 1, 빈_행: 2}   # 선택. 적은 것만 덮어쓴다. 아래는 기본값
        스타일:                    # 선택. 이름(라벨·입력·버튼·머리글·행) 단위로 정의를 통째로 바꾼다(위 "셀 스타일 정의")
          머리글: {채우기: 1F4E78, 글꼴_색: FFFFFF, 굵게: true, 테두리: 얇게, 가로: 가운데}
```

기본 스타일: 라벨 `{채우기: D9E1F2, 테두리: 얇게, 굵게: true, 세로: 가운데}`, 입력 `{채우기: FFFFFF, 테두리: 얇게}`, 버튼 `{채우기: D9D9D9,
테두리: 얇게, 가로: 가운데, 세로: 가운데}`, 머리글 `{채우기: 1F4E78, 글꼴_색: FFFFFF, 굵게: true, 테두리: 얇게, 가로: 가운데}`, 행 `{테두리: 얇게}`.

작업본(`### 개발사양서 · Display Screen` 아래):

```markdown
#### 화면 1 그림

##### 조회 조건
| 이름 | 필수 |
|---|---|
| 판매 조직 | Y |
| 판매처 | |

##### 버튼
| 이름 |
|---|
| 취소 |

##### 결과 표
| 열 |
|---|
| 판매문서 |
| 품목 |
```

- 소절은 `조회 조건`(머리글 `이름 | 필수`, `필수` 열은 생략할 수 있고 값은 `Y`·`N`·빈칸), `버튼`(`이름`), `결과 표`(`열`) 셋뿐이고 각각 없으면 건너뛴다.
  `#### <이름> 그림` 절 자체가 없으면 그 영역은 그리지 않고 템플릿 그대로 둔다.
- 배치: 영역 왼쪽 위부터. 조회 조건은 (라벨 + 입력) 묶음을 `간격` 칸씩 띄워 영역 너비에 들어가는 만큼 한 줄에 놓고 넘치면 다음 줄로 내린다. `필수: Y`
  인 라벨은 이름 뒤에 ` *` 가 붙는다. 조건 뒤에 빈 줄 한 줄. 버튼은 한 줄에 나란히(`간격` 칸씩). 결과 표는 열마다 `열` 칸 너비의 머리글과 그 아래
  빈 행 `빈_행` 줄(테두리만). 버튼과 결과 표 사이에는 빈 줄이 없다. `칸_수` 가 1 이면 그 칸은 병합하지 않는다.
- **멈춤(자르지 않는다).** 그림이 영역을 열·행 어느 쪽으로든 넘으면 산출을 거부(종료코드 1)하고 넘친 항목을 `problems` 에 밝힌다(영역을 넓히거나 항목을
  줄이거나 `칸_수` 를 줄인다). 영역 안에 값이 남아 있으면 거부(1, `비우기` 로 지운 템플릿을 쓴다). 기존 병합과 겹치면 읽지 못함(2). 지도에 없는 `#### X 그림`
  이름·세 소절 밖 이름·틀린 표 머리·표 밖 글은 조용히 무시하지 않고 읽지 못함(2)이다. `--check` 도 같은 검사를 한다.
- **지도 검증.** `화면:` 은 `이름`·`영역`(필수), `칸_수`(라벨·입력·버튼·열은 1 이상, 간격·빈_행은 0 이상의 정수), `스타일`(위 정의, 틀리면 멈춤)만 받고,
  영역이 같은 시트의 칸·표 데이터 영역·서술·`유지` 범위나 다른 화면 영역과 겹치면 지도 오류다(`비우기`·`서식_지우기` 와는 겹쳐도 된다 — 견본을 지운 뒤에 그린다).
  `form_columns` 규칙은 지도에 `화면:` 이 있을 때만 `#### <이름> 그림` 과 그 소절을 양식 안으로 보고, 없으면 "양식 밖" 으로 막는다.
- 서식은 `styles.xml` 에 항목을 덧붙여 쓴다. 엑셀에서 열어 모양을 한 번 확인한다.

## 원본이 SRS 인 지도 (요구사항 목록 양식)

Backlog List 처럼 **요구사항 1건 = 시트의 1행** 인 양식은 Spec 작업본이 아니라 `docs/ssot/SRS.md` 를 원본으로
삼는다. 표에 `원본: SRS` 를 적으면 된다. 이 표기가 없는 지도는 위의 작업본(`## 양식 항목`) 지도다.
한 지도에서 둘을 섞지 않는다.

```yaml
양식: Backlog
설명: SRS 요구사항을 Backlog List 의 Backlog 시트로
템플릿: ../BW_Backlog List_v0.1.xlsx
산출:
  폴더: docs/요구사항정의서
  파일명: "BW_Backlog List_v{버전}.xlsx"
  자리:
    버전: {메타: 버전}                 # SRS.md 문서 머리의 `버전: 0.2` 줄
시트:
  - 이름: Backlog
    표:
      - 이름: Backlog
        원본: SRS                      # SRS.md `## 요구사항` 표 + `### REQ-xxx` 상세 절이 원본
        머리글_행: 3
        시작_행: 4
        번호_열: Backlog ID            # md 의 ID(REQ-003)를 숫자 3 으로 쓰는 열. 생략하면 ID 는 엑셀에 안 간다
        md_전용: [출처]                # md 표에만 있고 엑셀에는 안 가는 열
        열:                            # 엑셀 머리글(정규화): 열 문자. 이 이름이 md 표 열 이름과 상세 절 소제목이 된다
          Backlog ID: A
          Title: F
          Short Description: H
          Status: J
          Priority (PO): O
  - 이름: Values Drop Down
    설명: 드롭다운 목록 — 건드리지 않는다
```

- **md 표.** SRS.md 의 `## 요구사항` 표 한 줄이 요구사항 한 건이다. 열 이름은 ① `ID`(`REQ-003`, 필수) ②
  지도 `열` 의 이름 ③ `md_전용` 에 적은 이름 중 하나여야 한다. 그 밖의 이름은 오타로 보고 산출이 읽지 못한다.
  지도에 없는 열은 엑셀로 가지 않으므로, md 에만 둘 열(예: 출처)은 `md_전용` 에 적는다. `다음 단계`
  (`개발`/`설정`/`미정`)는 `ID` 처럼 엔진 기본 md 전용 열이라 `md_전용` 에 안 적어도 되고 엑셀로 가지 않는다.
- **상세 절.** 긴 글 열(Short Description, Acceptance Criteria, Proposed Solution, Dependencies 등)은 표에
  넣지 않고 요구사항마다 `### REQ-003 <제목>` 아래 `#### <지도 열 이름>` 소제목에 쓴다. 본문은 그 열의 셀이
  되고 여러 줄은 셀 안 줄바꿈이다. 같은 열을 표 칸과 상세 절 양쪽에 쓰면 산출이 거부한다.
- **시트.** `원본: SRS` 표가 있는 시트만 쓴다. 그 밖의 시트(드롭다운 목록, 차트 등)는 지도에 `설명` 만 적고
  건드리지 않는다. 이런 지도에는 `칸`·`서술`·`원본` 없는 표를 둘 수 없다.
- **행.** `시작_행` 부터 요구사항 순서대로 쓴다. 쓰는 행에 숨김(`hidden`)이 있으면 풀고 고정 줄 높이(`ht`·`customHeight`)는 지워 엑셀이 내용에 맞추게 하고, 자동 필터는 쓴 행이
  그 범위를 넘을 때만 늘린다. 서식은 템플릿의 기존 행 서식을 그대로 쓴다.
- **번호.** `REQ-003` → 엑셀 숫자 3. `REQ-숫자` 모양이 아니거나 같은 ID 가 둘이면 산출이 거부한다.
- **버전.** SRS 에는 변경이력 표가 없을 수 있어, 산출 파일 이름의 버전은 SRS.md 문서 머리의 `버전: 0.2`
  줄에서 온다(`자리` 의 `{메타: 버전}`). 줄이 없으면 산출이 거부한다 — 스킬이 사용자에게 묻는다.
- **드롭다운.** 허용 값은 템플릿의 데이터 유효성에서 읽는다(표준·x14 확장, 정의 이름, 다른 시트 범위, 직접 적은
  목록). 지도에 따로 적지 않는다. `python -m checker.export --root … --form <지도> --list-values` 가 지도 `열`
  이름별 허용 값을 JSON 으로 낸다. 목록 밖 값은 산출 때 경고한다(아래).

## md 작업본 표기

기존 여섯 절(근거 요구사항, 개요, 상세 설계, 완료 조건, 참조, 변경 이력)은
그대로 두고 `## 양식 항목` 절을 `## 상세 설계` 뒤에 더한다. 양식을 여러 개
고르면 양식마다 반복한다.

```markdown
## 양식 항목

### 개발사양서 · Cover

양식 지도: [templates/forms/개발사양서.yaml](../../templates/forms/개발사양서.yaml)

| 항목 | 값 |
|---|---|
| 개발 ID | CO-006-01 |
| Title | 미정 |

#### Change History

| 요청일 | 주요내용 | 완료일 | 수정자 |
|---|---|---|---|
| 2026-10-06 | 최초 작성 |  |  |

#### 기능설명

1. ...

### 개발사양서 · Initial Screen

해당 없음
```

- `### <양식> · <시트 이름>` 소절, 칸은 `| 항목 | 값 |` 표, 표는
  `#### <표 이름>` + 머리글 그대로의 표, 서술은 `#### <서술 이름>` + 본문.
- 표 셀 안 줄바꿈은 `<br>` 로 쓴다.
- 서술 `위치` 가 범위면 한 줄에 항목 하나씩 쓴다(산출 때 줄마다 한 행이 된다).
- 지도 시트에 `화면:` 이 있으면 `#### <화면 이름> 그림` 아래 `##### 조회 조건`·`##### 버튼`·`##### 결과 표` 표로 화면 구성을 쓴다(위 "화면 그리기").
- `해당 없음` 은 시트 단위로만 쓴다(소절 본문에 한 줄). 칸·표 안에서는 쓰지 않고
  빈 칸으로 둔다.
- 값을 정할 수 없으면 추측하지 않고 사용자에게 묻고, 그래도 없으면 `미정`.
  필수 항목이 `미정` 이면 마무리 안내에 목록으로 알린다.
- 지도 파일을 못 읽거나 형식이 틀리면 통과로 넘기지 않고 읽지 못했다고
  알린다. 양식 없이 쓰지 않는다 — 사용자가 양식 없이 쓰라고 할 때만 그렇게 한다.

## 산출(#192)과의 경계

이 문서와 `/harness:spec` 의 작업 단계는 md 작업본까지만 다룬다. xlsx 는
`python -m checker.export`(스킬 "양식 파일 산출")가 만든다. 동작은 다음과 같다.

- 칸은 `위치` 에 쓰고 `형식` 이 있으면 `{값}` 을 바꿔 쓴다. `자동` 칸은 쓰지 않는다.
  `미정` 은 빈 칸이다. 값이 없는 칸은 템플릿 샘플을 비운다(`예시` 유무와 상관없다 — 빈 양식과 같은 모습).
- 표는 `시작_행` 부터 쓴다. 채우지 않은 템플릿 샘플 행(`최대_행` 이 있으면 그 범위)의
  열은 비운다. `최대_행` 이 없는 표가 템플릿 데이터 행보다 길어지면 마지막 데이터 행의
  서식을 복제해 행을 더한다. 표 아래에 지도의 다른 항목이 있으면 거부한다.
- 서술은 `위치` 가 한 셀이면 줄바꿈 포함 한 셀로 쓴다. 범위(예 `F38:I41`)면 템플릿이 줄마다
  한 행인 구조이므로 본문의 줄(빈 줄 제외, `<br>` 도 줄 나눔)을 범위의 첫 열에 행마다 하나씩
  쓰고 범위 안 나머지 샘플은 비운다. 줄 수가 범위 행 수를 넘으면 거부한다.
- 날짜(`YYYY-MM-DD`)는 칸 서식이 날짜 서식일 때만 날짜 값으로 쓰고, 정수는 숫자,
  나머지는 문자열로 쓴다.
- 거부(종료코드 1, 파일을 쓰지 않음): 필수 칸·표·서술이 `미정`/빈 칸, `최대_행` 초과,
  `짝` 표 행 수 불일치, 파일명 자리 값 없음, 파일 이름 금지 문자(`\ / : * ? " < > |`),
  같은 이름 파일이 이미 있고 그 경로가 `origin/main` 에 있음(main 에 있는 판은 덮지 않는다 — 버전을 올린다.
  `origin/main` 에 없는 판, 곧 이 브랜치에서 만든 판은 같은 버전으로 덮어쓰고 결과에 `replaced: true`. git 이 없거나
  `origin/main` 을 못 읽어 판단하지 못하면 덮지 않고 사유를 밝힌 거부이며, 엔진은 fetch 하지 않는다), 결과 파일명이 `검사_규칙` 의
  filename 패턴(`패턴`·`pattern` 둘 다 읽는다)과 다름, 셀 값이 32767자 초과, 표 행의
  셀 수가 머리글과 다름.
- `--form` 은 지도 이름(`Backlog`) 또는 지도 파일 경로(`templates/forms/Backlog.yaml`: `--root` 기준 상대·절대)를 받는다.
  경로는 `templates/forms/` 바로 아래의 실제 `.yaml` 파일이어야 하고, 아니면 종료코드 2. `--list-values` 도 같다.
- 읽지 못함(종료코드 2): 작업본·지도·템플릿을 못 읽음, 작업본의 양식·시트·칸·표·열이
  지도에 없음, 시트를 템플릿에서 못 찾음, `자동` 표시 없는 수식 칸에 쓰려 함,
  작업본 형식 오류(표가 끊긴 뒤 다시 나옴, 머리글 다음 줄이 구분선이 아님, 같은 소절이
  두 번, 칸 표 머리글이 `항목 | 값` 이 아님), 양식 이름에 경로 구분자가 있음, 템플릿·
  `검사_규칙`·`산출.폴더` 가 Project Repository 밖을 가리킴(절대경로·`..` 모두), 그 밖의
  예상하지 못한 오류. 검사 불능이며 통과도 위반도 아니다.
- 쓰기는 원자적이다. 모든 산출물을 같은 폴더의 임시 파일로 먼저 쓰고 전부 성공해야 최종
  이름으로 바꾼다. 하나라도 실패하면 이번 실행이 만든 파일을 모두 지운다.
- 수식이 있는 통합문서는 열 때 다시 계산하도록 표시한다(파일명을 읽는 수식 등).
  xlsx 자체의 검사는 훅이 아니라 PR 의 Actions(doc-guard)가 한다.
- 목록 밖 값(종료코드 3, #228): 산출한 표 값이 템플릿 드롭다운 목록에 없으면 파일은 쓰되 종료코드 3,
  `status: warning` 이고, `warnings` 의 `type: dropdown` 항목에 `item`(행 이름, 예 REQ-003)·`column`·`cell`·
  `value`·`allowed`(허용 값 전체)가 담긴다. 대소문자만 다른 값은 같은 경고에 "대소문자만 다르다" 힌트가 붙는다
  (비교는 정확히 일치).
  허용 값을 **읽지 못한** 칸(INDIRECT 등 읽을 수 없는 수식, 못 찾은 정의 이름, 범위가 아닌 수식, 유효성 XML 예외)은
  `type: dropdown-unchecked` 경고이고 이것도 종료코드 3 이다 — 검사하지 못한 것이지 통과가 아니고, `next` 가
  "검사하지 못한 열이 있다" 로 구분해 알린다. 목록 범위가 **실제로 비어 있는** 칸(값을 아직 안 채운 목록)은 검사할 허용 값이
  없다는 `type: dropdown-empty` 알림만 내고 종료코드에 영향이 없다. 엑셀이 목록 밖 값을 받는 유효성
  (`showErrorMessage` 꺼짐, `errorStyle` information·warning)은 검사하지 않는다(`--list-values` 에는 `enforced: false`).
  쓰는 줄이 같은 열의 유효성 범위 밖이면 `type: dropdown-missing` 알림(행 번호, "이 줄엔 드롭다운이 없다")을 낸다.
  `--check` 는 파일을 쓰지 않고 같은 보고만 낸다(`dry_run: true`). 먼저 `--check` 로 경고를 없앤 뒤
  산출하면 같은 이름 파일을 지울 일이 없다.
- 경고(`warnings`): XML 에 넣을 수 없는 제어 문자는 지우고 항목별로 알린다. 해당 없음이거나
  작업본에 없는 시트에 그림·도형이나 지도 밖 셀 값이 남아 있으면 "템플릿 샘플이 남아
  있다" 고 알린다.

### 한계: 지도 밖 템플릿 샘플

지도에 없는 그림·도형·셀 값은 산출 때 지우지 않고 템플릿에 있던 대로 남는다. 템플릿에서 지우려면 지도의 `비우기`·`그림_지우기` 로
지워 빈 양식을 먼저 만든다(위 "시트·서술의 선택 키", `python -m checker.blank_template`). 도형 삭제는 서식을 깨뜨릴 위험이
커서 지우지 않는다. 지도가 가리킨 칸·표 데이터 영역·서술 범위의 샘플만 비운다. 특히
화면 목업 시트(예: Display Screen)는 해당 없음으로 둬도 목업이 남으므로 `warnings` 가
나오면 엑셀에서 열어 직접 지운다. 목업 영역은 지도 `비우기`·`서식_지우기` 로 빈 양식에서 지워 두고, 화면 구성은 지도 `화면:` 과
작업본 `#### <화면> 그림` 으로 그린다(위 "화면 그리기").

### 빈 양식 만들기 (`checker.blank_template`)

```
python -m checker.blank_template --root <Project Repository> --form <양식> --src <견본 xlsx> --out <빈 xlsx> [--check]
```

`--out` 이 이미 있으면 거부한다(덮어쓰지 않는다). 결과는 stdout JSON 한 줄이다. 종료코드: 0 만들었고 남은 견본 없음, 1 거부
(`--out` 이 있음·`.xlsx` 아님·루트 밖, 범위 모양 오류), 2 읽지 못함·지원 안 함·지도 오류(겹침 등)·외부 참조를 쓰는 곳이 있음,
3 만들었으나 결과 패키지(sharedStrings·drawings·이름 정의·externalLinks)에 지운 견본 글자가 다시 보임(`leftovers` 에 파트와 글자).
`--check` 는 파일을 쓰지 않고 같은 처리·검사만 한다. 쓰기는 zip 수준이라 바뀐 파트 말고는 바이트 그대로이고(x14 드롭다운 보존),
엑셀에서 열었을 때 복구 창이 뜨는지는 엔진이 확인하지 못한다 — 사람이 한 번 열어 본다.

빈 양식을 만들 때 기본으로 하는 일(지도 키 없음): docProps 의 제목·작성자·마지막 수정자(core)와 Company·Manager(app)를 비운다(견본의
출처 정보라 빈 양식에 남을 이유가 없다). 엔진이 견본 여부를 판정하지 않는 곳에 내용이 있으면 `notices`(`type: review-needed`,
`kind`, `where`, "있음 — 확인 필요")로 알린다: 머리글·바닥글 글자, 머리글·바닥글 그림(`legacyDrawingHF`), 메모(주석), 드롭다운 목록 직접
입력 값, 시트 이름, 문서 속성(subject·description·keywords·category). 이 곳들이 견본인지 판정해 지우는 일은 남은 견본 검사(PR B) 몫이다.
`그림_지우기` 시트에 `legacyDrawingHF` 가 있으면 지원하지 않는다(2). 범위 문자열 모양 오류는 `blank_template` 에서는 거부(1)이고
`checker.export` 에서는 읽지 못함(2)이다. `docProps/app.xml` 의 TitlesOfParts·HeadingPairs(이름 목록)는 갱신하지 않는다.
