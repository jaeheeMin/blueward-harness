# /harness:handoff

지금 세션의 맥락을 **자기완결적인 인계 파일**로 메모리에 저장하고, 새 세션에
붙여 넣을 짧은 프롬프트를 준다. 새 세션은 이 대화를 보지 못한다. CLAUDE.md·메모리·
저장소는 따라가지만, **이 대화에서만 오간 결정·제약·측정치는 따라가지 않는다.**
핵심은 세션을 여는 일이 아니라 인계 파일의 품질이다.

이 스킬은 새 세션을 열거나 지금 세션을 `/clear` 하지 않는다(환경마다 달라 대부분의
팀원이 쓸 수 없다). 그것은 사용자가 한다.

## 절차

1. **인계할 게 있는지 본다.** 막 시작한 세션이라 이어 갈 것이 없으면 파일을 만들지
   않고 무엇을 이어 갈지 사용자에게 묻는다.
2. **저장 위치를 정한다.** 세션 시스템 프롬프트의 "persistent file-based memory"
   에 적힌 자동 메모리 폴더다. 그 폴더를 알 수 없으면(메모리 기능이 꺼진 환경) 위치를
   추측해 저장하지 말고, 아래 틀로 쓴 인계 전문을 그대로 붙여 넣을 프롬프트로 출력한 뒤
   7번으로 간다.
3. **같은 일의 이전 인계 파일이 있는지 본다.** 메모리 폴더의 `MEMORY.md` 와
   `handoff-*.md` 를 훑어, 같은 일이면 새로 만들지 않고 그 파일을 갱신한다.
4. **인계 파일을 쓴다.** 파일 이름은 `handoff-YYYY-MM-DD-<영문-요약>.md`(절대 날짜).
   frontmatter 는 메모리 형식이다.

   ```
   ---
   name: <제목>
   description: <한 줄 — 무엇을 이어 가는지>
   metadata:
     type: project
   ---
   ```

   본문은 전사가 아니라 요약이다. 코드 전문을 붙이지 말고 파일 경로와 위치를 준다.

   | 절 | 담을 것 |
   |---|---|
   | 한 줄 요약 | 무엇을 이어서 하는지 |
   | 지켜야 할 규칙 | 이 대화에서 사용자가 준 지시 중 계속 유효한 것(코드 바꾸기 전에 묻는다, 무엇을 임의로 추가하지 않는다, 뒷정리 규칙 등) |
   | 지금까지 | 끝난 것, 반영된 것, 수치, **검증한 방법**. 확인하지 못한 것은 "확인 못 했다" 고 그대로 적는다 |
   | 남은 일 | 다음에 할 것. 사용자 확인이 필요한 항목은 그렇게 표시한다 |
   | 도구·경로 | 실제로 쓴 명령, URL, 임시 파일 위치 |
   | 이 세션 상태 | 저장소, 브랜치, worktree, 커밋되지 않은 변경, 열린 PR |

   기준은 하나다 — **새 세션이 이걸 읽고 사용자에게 되묻지 않아도 되는가.**

   - 넣을 것: 사용자가 내린 결정과 그 이유, 이미 실패해서 버린 접근, 환경·브랜치,
     비교용 기준값, 아직 검증 못 한 부분.
   - 뺄 것: 소스 전문, 코드에서 바로 읽히는 구조, git 이력에 남는 것, 지난 대화의 잡담.
   - 날짜는 "오늘" 이 아니라 절대 날짜로 쓴다.
   - 이슈·PR 은 번호만 쓰지 말고 무엇인지 설명과 GitHub 링크를 붙인다.
   - **비밀(토큰·쿠키·비밀번호)은 넣지 않는다.** 새 세션이 스스로 로그인하게 한다.
5. **`MEMORY.md` 에 한 줄을 넣는다.** `- [제목](handoff-....md) — 한 줄 훅` 형식이다.
   이미 그 파일의 줄이 있으면 새로 추가하지 말고 갱신한다.
6. **일반 사실은 따로 쓴다.** 계속 유효한 사실(사용자 선호, 환경 제약)은 인계 파일에만
   넣지 말고 별도 메모리로도 남기라고 사용자에게 안내한다. 그래야 인계 파일이 끝난 뒤에도 남는다.
7. **사용자에게 줄 것.** 아래 둘을 출력한다.
   - 새 세션에 붙여 넣을 짧은 프롬프트(코드 블록). 한 줄 요약, "이어서 진행. 먼저
     메모리의 `handoff-....md` 를 읽어." 와 핵심 규칙 2~3줄이면 된다.
   - 안내 한 줄 — "`/clear` 하고 붙여 넣거나, 새 세션 창을 열어 붙여 넣어."
8. **이 세션은 그 작업을 더 진행하지 않는다고 말한다.** 같은 일을 두 세션에서 동시에
   하면 서로 덮어쓴다. 사용자가 계속 말을 걸면 응답은 하되, 파일을 고치기 전에 새
   세션과 겹치지 않는지 확인한다.

## 이럴 땐 쓰지 않는다

- 못 끝낸 일을 GitHub 이슈로 남기려는 말("남은 건 이슈로 남겨줘")이면 wrapup 스킬로.
- 작업을 끝내 커밋·푸시·PR 로 넘기려는 말이면 deliver 스킬로.
- 대화 전체를 이 세션 안에서 줄이려는 것이면 `/compact` 가 맞다. 이 스킬은 새 세션으로의 인계다.
