# 위임 규칙

이 문서는 이 저장소에서 에이전트가 일하는 방식을 규정한다.

이 저장소는 각자의 개인 전역 설정과 무관하게 동작해야 한다. 참여자마다
전역 설정이 다르기 때문에, 저장소의 규칙과 스킬은 외부 설정을 전제하지
않고 그 자체로 완결되어야 한다. 필요한 제약은 모두 이 저장소 안에 적는다.

## 역할 분리

메인 세션은 오케스트레이션만 맡고, 실무는 서브에이전트에 넘긴다.

| 메인 세션이 직접 한다 | 서브에이전트에 넘긴다 |
|---|---|
| 무엇을 왜 조사할지 정하는 판단 | 조사에 필요한 자료 수집 |
| 조사 결과의 취합과 판정 | 파일 읽기, 코드 탐색, 명령 실행 |
| 다음에 무엇을 조사할지 정하는 재지시 | 구현과 수정 반영 |
| 설계와 사용자 승인 | 검증에서 나온 수정사항 반영 |

예를 들어 어떤 주제를 조사해야 할 때, 실제로 파일을 열고 명령을 실행해
사실을 모아 오는 부분은 서브에이전트가 수행한다. 메인 세션은 그 결과를
읽고 판정하며, 부족한 부분이 있으면 다시 서브에이전트를 띄운다.

## 모델

메인 세션의 모델은 제한하지 않는다. 오케스트레이션은 상위 모델에서
수행해도 되고 그 선택은 사용자에게 맡긴다.

**서브에이전트의 모델은 `sonnet` 으로 고정한다.** 조사와 실행은 판정이
끝난 뒤의 수행이므로 상위 모델이 필요하지 않고, 상위 모델을 여러 개
띄우면 한도가 빠르게 소진되기 때문이다.

## 서브에이전트 정의

harness Plugin 은 `agents/` 에 서브에이전트 세 개를 정의해 둔다. 서브에이전트를
띄울 때는 이 정의를 골라 쓴다. 정의 파일이 모델과 쓸 수 있는 도구를 고정하므로
프롬프트마다 적을 필요가 없다.

| 에이전트 | 언제 쓰나 | 쓰기 도구 |
|---|---|---|
| `harness:researcher` | 파일·코드·GitHub 상태·공식 문서를 읽어 사실을 모아 올 때 | 없음(Write, Edit 제외) |
| `harness:reviewer` | 구현이 끝난 diff 를 정확성·보안·원칙 위반으로 검토할 때 | 없음(Write, Edit 제외) |
| `harness:implementer` | 범위를 정해 준 코드·문서 수정과 테스트 실행을 맡길 때 | 있음(전부) |

세 에이전트 모두 모델은 `sonnet` 이다. 구현은 `harness:implementer` 가, 검토는
`harness:reviewer` 가 맡아 편집과 검토를 분리한다. 에이전트는 `@agent-harness:researcher`
처럼 사용자가 직접 부를 수도 있다.

## 자기 승인 금지

서브에이전트가 만든 결과를 그 서브에이전트가 승인하지 않는다. 편집을
수행한 에이전트와 그것을 검토하는 에이전트를 끝까지 분리한다. 검토는
메인 세션이 하거나 별도의 검토 에이전트에 맡긴다.

PR 병합도 기본은 사람이 한다. 에이전트가 자기 PR 을 예외적으로 병합해도
되는 좁은 조건은 `governance.md` 의 "예외: 에이전트가 자기 PR 을 병합해도
되는 경우" 절을 따른다.

## 프롬프트에 사실을 다 적는다

서브에이전트에는 대화 맥락이 넘어가지 않는다. 파일 경로, 확인해야 할
대상, 지켜야 할 제약, 건드리면 안 되는 범위를 프롬프트에 모두 적는다.
"앞에서 정한 대로" 같은 지시는 통하지 않는다.

## 이 규칙의 강제 방식

모델과 쓰기 금지는 `agents/` 의 정의 파일이 고정한다. `researcher` 와
`reviewer` 는 `disallowedTools` 로 Write, Edit, NotebookEdit 를 뺐고(허용 목록 `tools`
를 쓰면 이름이 사용자마다 다른 MCP 조회 도구까지 막힌다), 셋 다 `model: sonnet` 이다. 다만
다음 한계가 있다.

- Agent 도구를 부를 때 `model` 을 넘기면 정의 파일의 model 보다 **우선한다**
  (공식 문서의 우선순위: 호출 때 넘긴 model > 정의 파일 > `CLAUDE_CODE_SUBAGENT_MODEL`
  > 메인 모델). 호출 때 `model` 을 넘기지 않는다.
- 정의를 쓰지 않고 `general-purpose` 같은 기본 에이전트를 띄우면 이 고정이 걸리지
  않는다. 위 표의 정의를 골라 쓴다.
- 읽기 전용 에이전트도 Bash 는 쓸 수 있다. 상태를 바꾸는 명령 금지는 도구가
  아니라 정의 본문의 지침이다.

훅으로 더 강제하려면 메인 세션이 어떤 도구를 쓰는지를 가로채야 하는데, 정당한
직접 확인까지 막게 되어 부작용이 크다. 반복해서 지켜지지 않는 것이 확인되면 그때
훅을 검토한다.
